## 1. 已确认方向

把内置播放定位为“媒体库里的可靠观看工具”：**应用主窗口内的播放器、一套 libmpv 内核、端侧解码、本地与远程一致的操作。** 不新建独立操作系统播放窗口，不做第二套影片资料页或完整媒体中心。

用户已确认以下三项及收起画面的补充要求，替代初稿中的相反建议，不再重复询问：

| 决策 | 方案约束 |
| --- | --- |
| 参考 Plex，内置播放并可收起到底部操作栏 | 提供应用内展开、底栏收起、全屏三种展示形态；收起不停止或重建会话，可恢复观看并继续浏览媒体库。 |
| 收起时同时显示实时小视频 | 底栏包含持续播放的原生小视频与操作控件，不降级为仅声音、封面或静态截图。 |
| 默认关闭续播记录 | 初始设置不读取或持久写入续播点，不提示继续；只有用户主动开启才启用本机续播。 |
| 三平台同时 | Windows、macOS、Linux 使用同一功能范围、同一发布关口；不得先对公众开放 macOS 再补其它平台。 |

本方案中的“本地播放”指桌面客户端内置播放，包括本机影片文件和远程媒体库原始文件；不是仅播放本机磁盘文件。Web 暂不动，服务器不解码、不转码、不转封装、不代理任意外部 URL。

建议首版完成基础观看闭环：打开指定影片资源 → 播放/暂停与定位 → 选择音轨/字幕 → 可控续播 → 正确结束和释放。队列、截图、画中画与高级画质设置分开推进。

这里的“缩到底部”是应用内收起，不是操作系统最小化、画中画或销毁播放器。已确认底栏同时显示实时小视频：收起时缩小同一个原生视频视图，声音、位置和暂停意图保持；恢复时不重载影片。

原生技术关口也相应前移：**须在真实应用壳中验证展开 ↔ 底栏 ↔ 全屏的连续切换、原生视图避让与页面交互。** 旧原型只验证独立测试窗口，不足以证明这套形态已经可用；HTML 控件不能靠 `z-index` 盖住原生画面。

| --- | --- | --- |
| 本机模式 `local` | 内置播放本机文件 | 由主进程复核媒体库/影片/资源归属与文件可用性，遵循本机根目录安全规则。 |
| 远程模式 `local` | 主进程取得 PlayGrant，libmpv 读取原始文件的 HTTP Range | 保留活动库、成员、根目录与 `locatorRevision` 校验；播放凭据不交给 renderer。 |
| `direct` / STRM 视频直链 | 首个闭环暂保留现有外部打开；作为后续小阶段候选 | 与服务端原文件播放不是同一种授权路径。后续只考虑明确 HTTP/HTTPS 文件直链，不默认支持直播、播放列表、DRM、登录 Cookie 或网页提取。 |
| `web`、`magnet`、`ed2k` | 保留系统/外部应用打开 | 不伪装成 libmpv 可直接播放的影片文件。相关链接也不是影片资源。 |

当前 [catalogPlay.ts](../packages/library/src/catalog/catalogPlay.ts) 的扩展名映射用于 MIME 提示，未知后缀回退 `application/octet-stream`，不是授权格式白名单。来源授权与内核解码能力分开：不能由允许传输就宣称某格式已支持。第一轮实际验收覆盖 MP4/H.264/AAC 与 MKV/HEVC/AAC，其余格式按真实素材报告，不绕过资源授权或任意读取文件。

建议首次仅从已纳入媒体库的影片资源进入；不增加独立“打开任意文件”、系统默认播放器注册或文件夹自动连播功能。

## 4. 界面与交互设计

### 4.1 应用内展开与底栏结构

```text
展开观看（同一个 Javdex 主窗口内）
┌ 系统标题栏：Javdex ────────────────────────────────┐
│ 番号/资源名（可隐藏）             收起  全屏  停止   │
│                                                  │
│              原生视频区：原比例显示                │
│             字幕在内核视频面内合成                 │
│                                                  │
├──────────────────────────────────────────────────┤
│ 00:12:34 ───────────────●────────────── 01:42:00    │
│ ▶  −5s  +5s   音量    1×   音轨 字幕  ⋯            │
└──────────────────────────────────────────────────┘

收起浏览（已确认实时小视频）
┌ 系统标题栏：Javdex ────────────────────────────────┐
│ 侧栏 │ 当前媒体库/详情/设置，继续正常浏览和操作       │
│      │ 保留当前 URL、筛选、列表位置及表单草稿        │
├──────────────────────────────────────────────────┤
│ [实时小视频] 资源名…  ▶  ──●── 00:12:34 音量 ↑ ×  │
└──────────────────────────────────────────────────┘
```

- 展开播放器是应用内观看层，不是新的 OS 窗口；收起后恢复媒体库交互，底栏跨页面存在。首版保持一个活动播放会话，不同时显示两套播放器。
- 沿用 Javdex 的密集、安静、工具化风格；控制区使用语义 token、现有按钮/选择控件和 CSS Modules，视频区保持黑色背景，不随浅色主题变成亮色画布。
- 不另加重复的大标题、海报、演员资料或编辑工具栏。标题长时截断；本机/远程作为低频信息，不以文件路径占据顶栏。
- 底栏左侧为实时小视频，中间为资源名、播放/暂停、进度和时间，右侧为音量、恢复展开、停止；倍速、轨道、字幕等放展开面或更多，不用窄栏塞满所有命令。小视频保持原比例并允许黑边，不拉伸或裁切；窄窗口优先收起低频文字和选项，不能自动移除已要求的实时画面。无会话时底栏不出现；停止后释放实际布局空间，不能留下黑块或空占位。
- 点击实时小视频恢复展开，不先触发播放/暂停；独立播放按钮负责暂停。底栏中字幕继续由内核合成，不用 HTML 文本覆盖原生小视频；字号与显示范围不能侵入相邻控件。底栏尺寸由控件密度 token 和视频插槽几何共同持有，页面不各自写一份高度。
- 底栏是应用壳统一持有的布局区域，缩小浏览可用视口，而不是 `position: fixed` 盖在各页底部。虚拟列表按视口变化重算但保持条目锚点；各页面不得各自追加底部 padding，也不得盖住设置保存栏。
- “收起”和“停止”使用不同图标与可访问名称：前者保留会话、声音和时间，后者停止、释放并移除底栏。再点当前影片的播放按钮或底栏恢复按钮，只展开现有会话。
- “更多”包含章节、来源选择、指定时间、播放信息、外挂字幕、外部打开和进度记录控制。常用按钮留在应用里，不只藏在 macOS 系统菜单。
- 展开面中的音轨/字幕/更多面板位于画面外的侧栏或控制区；窗口变窄时优先收起低频项。侧栏打开会重新计算原生视口，不盖住画面。
- HTML 模态层打开时原生画面必须避让，背景 inert、焦点返回和 Esc 沿用交互层合同。避让只改变可见性，不隐式改变暂停意图；收起后浏览媒体库的普通弹窗不自动中断声音。需暂停的任务明确调用会话控制；资料库恢复或身份失效则停止会话。
- 原生区鼠标事件由宿主显式转成受限操作：单击播放/暂停、双击全屏。避免单击立即暂停后又执行双击；拖动、文字选择和控制区事件不穿透到画面。

### 4.2 展示状态与返回行为

展示形态与播放状态是两个维度：`expanded / docked / fullscreen` 不等于 `playing / paused / buffering / ended`。收起暂停片仍暂停，收起播放片仍播放；切换形态不重新 `loadfile`、不重置倍速/轨道、不再触发已开始事件。

| 用户动作 | 展示结果 | 播放会话 |
| --- | --- | --- |
| 首次点击影片资源播放 | 应用内展开 | 打开一次；默认不读续播，从头开始。 |
| 展开面点收起 | 带实时小视频的底部播放栏，恢复浏览 | 同一原生视图缩小；位置/暂停意图/音轨等保持。 |
| 底栏点恢复或再点同一资源播放 | 恢复展开 | 同一 session ID，不重开来源、不重新授权。 |
| 进入全屏 / 退出全屏 | 全屏 / 展开 | 同一会话；只调整宿主区域。 |
| 全屏中收起 | 退出系统全屏，再到底栏 | 同一会话，不留全屏空壳。 |
| 展开面返回 / Esc | 收起到底栏 | 不停止；先关闭子面板，再退出全屏，再收起。 |
| 收起后正常列表导航 | 底栏保持，页面正常导航 | 不受路由组件挂载影响；权限与资料库身份仍复核。 |
| 点停止 / 真正退出应用 | 浏览面无播放栏 | 停止并释放；默认不持久记录位置。 |

展开/收起属于临时交互状态，不把播放 URL、进度或授权信息写进路由 query。底层列表/详情保持原路由和挂载；展开覆盖浏览面时，其后台交互 inert，收起后恢复焦点和原浏览位置。若用户主动导航到另一页面，仍走现有 settings/plugin 离开保护，先收起观看层再导航，不绕过草稿守卫。

系统后退、鼠标返回键或 macOS 返回手势在展开时应先收起，而不是退出影片详情；底栏状态不消费普通页面返回。展示历史由稳定所有者协调唯一实例 token 与关闭来源，遵循 [图片预览历史规范](IMAGE_PREVIEW_HISTORY_DESIGN.md)，不在组件 mount/cleanup 里 `pushState` 或 `history.back()`，不和图片预览、设置离开保护各自抢写历史。S0 需验证这些使用者共存，而非仅验证播放画面。

### 4.3 全屏控制的技术关口

成熟播放器有可自动隐藏的全屏控制条，见 [VLC 全屏说明](https://docs.videolan.me/vlc-user/desktop/3.0/en/basic/video.html#full-screen) 和 [mpv OSC](https://mpv.io/manual/stable/#on-screen-controller)。

用户已选择应用内播放器及底栏收起，**并未明确批准全屏永久固定底栏**。建议产品目标为全屏控制可唤出、可自动隐藏：暂停、鼠标/键盘操作、菜单打开或控件有焦点时保持可达；不因自动隐藏留下空白占位或吞掉第一次点击。

S0 前置评估内核 OSD/原生控件或平台合成方案，验证控件、字幕避让、输入和无障碍是否可在三平台成立。若不能安全完成，应展示证据并请用户决定全屏固定控件是否可接受；不得自行降级、单平台发布或换用另一套内核。**不预先承诺 WebContentsView、额外窗口或 `z-index` 可以解决跨平台叠层。** 普通展开面先以画面外控件验证完整链路。

### 4.4 快捷键与焦点

建议固定首版键位：Space 播放/暂停，←/→ ±5 秒，Shift+←/→ ±30 秒，M 静音，F 全屏，Esc 先关闭最上层面板，再退出全屏、收起展开面。它们是 Javdex 的建议键位，不是逐项复刻 mpv 默认配置。

输入框、组合输入与控件自身方向键优先。滑杆键盘调整不同时触发影片快进；窗口失焦不处理快捷键；弹层里按 Space 不穿透到播放。收起状态只有焦点处于底栏时才接管播放键，不能在媒体库搜索、列表选择或表单中偷走 Space/方向键。常用动作的可访问名称、当前状态、错误提示须对屏幕阅读器可读。

## 5. 续播、隐私与业务行为

### 5.1 续播不是完整历史

已确认**续播记录默认关闭**：新安装和没有该配置项的旧设置都取关闭；不读取旧续播点、不创建或写入进度文件，新的播放会话从头开始。内存中的当前会话位置仍正常更新，因此收起、恢复和全屏切换不从头重播，这不属于持久记录。

用户主动开启后，将播放器偏好放在“此电脑”，续播数据放在独立设备文件；不写影片元数据表、不增加远程服务端观看记录，也不让远程模式打开本机 `library.db`。音量等设备偏好与敏感的续播数据分开，关闭记录不等于禁止保存所有播放器设置。

当前记录键：`CatalogIdentity(mode, catalogId, serverId?) + resourceId + locatorRevision` 的摘要；本机额外合入实际文件身份（canonical path、dev／ino、大小、mtime）的摘要输入，用于发现未重新扫描的文件替换。这不是内容指纹，路径不直接写入进度文件：

- 不用番号、影片标题、影片 ID、绝对路径或临时授权 URL 作为唯一键。同一影片不同影片资源各有自己的位置，不复制进度。
- 资源修订变化则不沿用位置，包括 STRM 目标变化；单纯改名也可能使现有 revision 变化，首版宁可不续接，不新增内容指纹或猜测同片映射。
- 资料库恢复后的新 `catalogId` 不复用旧数值 ID 的位置；`writerEpoch` 用于授权有效性，不当作内容身份。
- 键和记录中不保存播放 token、writer secret、完整个人路径或远程地址。位置仍是敏感设备数据，不声称文件加密或完全匿名。

开启后，记录只包含 schema 版本、身份键、位置、已知时长和更新时间。建议每 10 秒低频保存，暂停/停止时补写，采用原子写入；最多保留最近 1000 条、90 天，均为可评审的启用后默认值，不扩张成历史浏览系统。

开启记录后的续播规则建议：

1. 有实际开始播放的会话才记录；只打开窗口、加载暂停首帧或拖动预览不算。
2. 起点附近不提供续播；建议位置小于 30 秒时不保存续播点。自然 EOF 清除该资源续播点，接近结尾不再提示续播；阈值写入可测试策略，不据此生成“已观看”状态。
3. 有有效位置时先暂停准备，在控制区显示“继续 12:34 / 从头播放”，不弹阻塞式全局对话框；选择后才真正开始。无位置则正常自动播放。
4. 已开启记录的用户可选“本次不保存进度”；该会话不读取、删除或改写旧位置，包括自然 EOF 也不清除旧点。若播放中才关闭本次记录，不撤销已发生的写入；清除需另行明确执行。提供清除当前资源/全部本机进度的动作。
5. 全局关闭后不读取续播点、不执行位置文件的新增/更新/过期清理；已有记录是否清除由用户另行确认。开启从之后的播放开始记录，不回填之前的播放行为。不写系统最近文件，不默认公开影片标题/封面到系统媒体信息。

“防窥模式”仍是现有视觉遮挡含义，不自动等同于“不保存进度”。播放器标题隐藏、暂停隐私遮罩和临时无记录播放是不同控制；播放授权的必要服务端状态与日志仍沿既有规则，不因关闭续播而取消授权校验，也不能承诺抹除操作系统或服务器日志。首版不自动生成/持久化视频缩略图。

### 5.2 稍后观看与资源主次

当前 [playerHandlers.ts](../apps/desktop/src/main/ipc/playerHandlers.ts) 在外部程序/系统接受打开后，按用户已启用的“播放后移除”策略移除稍后观看；这不是实际解码或播放完成证据。

内置播放建议以**当前会话真实画面输出并且播放时钟推进**作为已开始事件，一次性触发同一移除策略：展开面和底栏实时小视频都可提供画面证据，不要求先恢复展开才算开始。加载成功、输出配置值、首帧暂停、失败、旧会话事件和 seek 完成均不能代替实际开始。声音输出另行验收；收起/恢复不重复触发。外部播放保持原“已接受打开”语义，因为无法可靠观察第三方播放进度；界面和文档须说明区别。

本阶段按已授权方案实现该实际开始语义。关闭续播记录不等于禁止已有稍后观看规则；两者分别展示和控制。不新增“看完比例”、自动清单移动或隐式收藏。

播放器内切换资源只影响本次会话，不改变主影片资源；要设主仍走现有独立动作。保持 [ADR-0014](adr/0014-unified-video-resource-runtime-contract.md)：打开失败不自动换备用资源。新资源从自己的位置或起点播放，不照搬另一版本时间。

## 6. 代码架构建议

### 6.1 只增加真实需要的边界

```text
媒体库播放入口 → playerService（路由内置 / 外部）
                    └─ PlaybackSession（会话与业务）
                        ├─ 来源解析：本机文件 / 远程 PlayGrant
                        ├─ libmpv 适配：命令、轨道、运行状态
                        ├─ 原生视图宿主：主窗口内视图、视口、输入
                        └─ 本机续播存储：显式启用后读写/过期/清除
应用壳中的播放器 ← 受限 IPC：会话 ID、控制命令、状态快照
    └─ 展示所有者：展开 / 底栏 / 全屏，视口与返回协调
```

- **会话模块要深、对外接口要小**：候选接口为 `open(媒体库/影片/资源 ID) → sessionId`、`control(sessionId, 受限命令)`、订阅状态、`close(sessionId)`。播放面展开成功不等于播放开始。调用端不需要理解 mpv 属性名、凭据续签或销毁顺序。
- 展示所有者稳定地位于应用壳、页面路由之上；`setPresentation(expanded/docked/fullscreen)` 仅改变同一会话的原生视图矩形与必要的可见性，不新建第二个 libmpv core、转发授权 URL 或重开来源。收起时仍持续向底栏视频插槽呈现画面，不读取截图、传输帧到 renderer 或额外启动预览解码器。会话不由影片详情、底栏或播放面组件的 mount/cleanup 持有。
- 来源解析只在 main 内处理路径、授权与资料库身份。renderer 不提交任意路径/URL，不持有播放句柄；已有安全文件选择器把外挂字幕转成当前会话可用的受控引用。
- 内核适配只负责播放器能力，不访问资料库、不写稍后观看。原生宿主只处理 OS 视图和输入，不判断影片身份；会话负责将实际播放事件交给现有业务策略。
- `PlayerState` 包含会话/来源代次、阶段、暂停意图、缓冲/跳转状态、时间、音量、速率、轨道和能力；展示形态另有状态，不与 `paused` 共用。未知信息用空值；“用户暂停”和“网络缓冲”不能共用一个布尔量。UI 以会话状态为权威，仅拖动目标是临时草稿。
- 指令按类型白名单与参数范围校验，并验证发送窗口归属；不暴露任意 `mpvCommand(string[])`、任意属性读写或通用 Node API。过期会话/来源事件不得改新会话的位置、续播或清单。
- 只在桌面合同分组增加必要类型。暂不建立 Web/桌面多引擎工厂、通用 `packages/player`、插件化播放内核或第二套服务器播放 API。

建议代码归属：正式会话/native adapter 留在 `apps/desktop/src/main/player/`，播放面/底栏与稳定的展示所有者在 desktop renderer，IPC 类型在 `packages/contracts/src/desktop/`；继续使用 `playerService` 的资源入口。在 [Layout.tsx](../apps/desktop/src/renderer/src/components/Layout.tsx) 的应用壳增加统一播放槽，不在每个详情或列表页各建播放器，不用播放路由替换/卸载原浏览树。原型只作为实验与回归证据，不能直接把独立测试宿主变成正式应用启动流程。

设备播放偏好扩展现有 [thisComputerSettingsStore.ts](../apps/desktop/src/main/desktop/thisComputerSettingsStore.ts) 与 [desktop/settings.ts](../packages/contracts/src/desktop/settings.ts)。不要将内置/外部偏好、音量和记录开关写成服务端资料库设置；续播数据与偏好分开，避免每次位置更新重写连接配置。

### 6.2 原生与安全边界

- 正常帧不经 IPC/JavaScript 拷贝；位置更新约 4–10 Hz，轨道/错误按变化推送，native 不逐帧驱动 React。日志默认脱敏、限量，诊断复制不得含凭据或完整个人路径。
- 固定并维护 mpv 配置，禁止读取用户任意 mpv 配置/脚本、网页提取工具与未经授权的附加资源；首版不启动下载器或让媒体文件产生新授权入口。用结构化参数加载文件，不拼命令字符串。[mpv 路径与配置说明](https://mpv.io/manual/stable/#paths)
- 原生绘制与控制线程的上下文、回调、销毁规则按实际版本 headers 实现，不能在更新回调中任意重入控制；正式接入必须验证库内扫描/刮削同时工作时的响应性，不能照搬原型主线程绘制就承诺长片性能。[render API 线程规则](https://github.com/mpv-player/mpv/blob/master/include/mpv/render.h)
- 收起时保留 core/渲染上下文和原生视图宿主，把同一视频视图缩放、定位到底栏插槽并持续绘制；更新坐标需复核当前展示代次、实际窗口边界与 DPI，旧布局回调不能让视频回到展开区或盖住控件。普通收起不隐藏画面、不停止解码、不重载影片，也不因 React 卸载释放上下文。弹层避让等临时隐藏仍须正确处理更新，不能停掉全部回调导致内核等待。官方说明活动渲染上下文释放会禁用视频，更新处理也有阻塞约束，因此缩放、避让与恢复必须在三平台实测。[mpv 0.41 render API](https://raw.githubusercontent.com/mpv-player/mpv/v0.41.0/include/mpv/render.h)
- 当前原生 addon 位于 Electron main 内，原生崩溃可能影响整个应用。应用内播放同样不等于进程隔离，不能把同一进程的 NSView 指针直接发给 utility process。若要求崩溃隔离，需要另行设计渲染面的跨进程所有权；首版不承诺无成本完成。
- 本机根目录身份、远程授权归属与 revision 继续守卫。权限/资料库身份变化应停止旧会话，不能自动退回本机库。重试只针对同一经复核资源；续签需主进程重新授权、有限次数且不延长已撤销权限。错误原因不明确时提供显式重试，不无限自动重载。

这些边界延续 [ADR-0027](adr/0027-isolate-read-only-lan-web-access.md) 和 [ADR-0029](adr/0029-server-mode-extends-root-and-web-isolation.md)，不改变 Web 的只读与无转码合同。

## 7. 失败反馈与兼容策略

| 情形 | 应有反馈与动作 |
| --- | --- |
| 文件丢失 / 根目录不可访问 | 区分缺失与离线；停止会话，允许重新检查，不自动删除资源。 |
| 远程授权失败 / 文件版本变化 | 显示需重连、资源变化或不可用；重新核实同一资源，不继续用旧句柄。 |
| 编码或音频不支持 | 显示当前已识别信息与实际原因；允许显式外部播放器打开，不自动转码或换另一资源。 |
| 远程缓冲 | 保留位置和用户暂停意图，显示缓冲状态；不要谎报“暂停成功”或“播放完成”。 |
| 自然结束 | 停留结束状态，提供重播/关闭；不自动连播下一部。 |
| 收起 / 恢复 / 页面导航 | 同一会话不中断，底栏实时画面继续呈现；不能触发停止、重新授权或位置持久保存，弹层临时避让也不等于结束播放。 |
| 切换影片 / 停止 / 退出应用 | 停止旧输入和输出，仅开启记录时保存位置，清理监听/原生上下文/播放授权生命周期；旧事件失效。 |

播放器选择作为“此电脑”的独立设置：内置 / 外部。2026-10-06 用户确认验收完成后，新安装默认内置；已有用户升级保留已保存的播放方式与程序路径，缺少播放方式字段的旧设置仍用外部，用户可主动切换。续播开关独立且默认关闭。不改变系统文件关联。不支持内置的开发构建明确显示不可用，保留外部入口，不运行时静默切换；不能以这种开发差异绕过三平台同时发布要求。

## 8. 后续增强与明确不做

后续按真实使用收益排序，均不自动纳入首版：

1. 本机同名字幕自动发现、语言偏好；服务端字幕 sidecar 另设受资源身份约束的授权发现/下载合同。
2. A–B 循环、逐帧、音画延迟和手动音频设备选择；独立置顶小窗口需另行立项，不把已要求的底栏收起等同于画中画。
3. 用户主动截图（明确是否带字幕、位置/剪贴板）；不自动写影片海报、样张或媒体资源。
4. 显式播放队列（不是新的持久清单，也不自动把当前筛选/目录变队列）；用户决定是否连播。
5. 画中画、缩略图预览；分别验证平台窗口、额外解码与远程读取预算。应用内收起属于首版已确认范围；全屏控件合成在 S0 前置评估，不能一概后置。
6. HTTP/HTTPS 文件直链内置播放；继续与网页、直播/播放列表及登录鉴权区分。

暂不做：Web 改造、服务器转码/转封装、完整历史和跨设备进度同步、播放完成百分比业务、自动在线字幕下载、投屏/DLNA/AirPlay、录屏/剪辑/转码、光盘导航、第三方脚本、shader 配置器、HDR/杜比视界与 HDMI 直通的正式支持承诺。不是宣称内核不支持，而是本阶段不承担完整产品验收。

## 9. 分阶段执行与验收

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| S0：应用内与跨平台关口 | 三平台原生主窗口嵌入、展开/实时小视频底栏/全屏连续切换及弹层避让；确定可分发库、依赖与许可证 | 三平台同一会话持续运行，底栏真实画面推进、不挡页面、恢复不重新加载；全屏控件合成有证据。若需体验降级，先请用户确认，不能自行换回独立窗口或仅声音底栏。 |
| S1：正式垂直链路 | 接 `playerService`、应用壳播放槽、正式本机/远程来源；基础控制、底栏/全屏、返回协调；实际开始事件 | 三平台真实入口和原文件可用，明确选定资源；真实画面、音频时钟和人工听感分别验证；仅展示切换不重开请求或重复移除稍后观看。 |
| S2：完整首版体验 | 轨道/字幕、倍速、章节、指定时间、默认关闭的可选续播、反馈/信息、键盘/无障碍、休眠行为 | 三平台功能表一致；默认不产生位置文件；开启后进度不串用；旧用户外部播放器配置保留；凭据不进入 renderer 或诊断。 |
| S3：共同发布关口 | 三平台安装包、原生依赖固定与更新策略、文档与支持清单 | 同一源码版本的全部目标包在干净机器验收通过，无需 Homebrew/开发依赖；本机及独立远程部署可播，关闭/恢复/底栏链路通过；之后才共同公开发布。 |

已确认三平台同时发布。内部研发可以利用 macOS 原型先验证某个细节，但 Windows/Linux 的原生关口必须尽早并行，不等 macOS 功能做完才研究。任一平台核心链路不通过，内置播放整项不进入公开版本；“其它平台继续外部播放”不能冒充三平台同时支持内置。在平台/库分发未确定前不承诺日期，也不直接将原型合入 main。

按当前 [打包目标](../build/packaging.targets.json) 的启用项，验收矩阵为 Windows x64（NSIS、ZIP）、macOS x64/arm64（DMG）、Linux x64（AppImage、deb）。包型和架构不是只测三个开发机就算完成。Linux 首版显示范围已经用户确认是 X11／XWayland，原生 Wayland 后续补齐；具体发行版、缩放和 GPU 支持仍须实际核对，不把无 GUI 容器构建外推为 Linux 原生交互通过。

分发不能直接打包开发机 Homebrew 动态库。Javdex 已确认采用 GPL-3.0-or-later，应用许可文本、包元数据和当前公开说明已同步；第三方及历史版权/许可声明保留。mpv 官方说明默认 GPL 构建、可选 LGPL 构建及依赖影响；仍需要按实际二进制、构建选项和全部依赖核对再分发，不能仅凭采用 GPL 或“动态链接”判断合规。[官方 Copyright](https://github.com/mpv-player/mpv/blob/v0.41.0/Copyright)

### 验收素材与证据

- MP4/H.264/AAC、MKV/HEVC Main10/AAC：本机文件和独立服务器原文件；补充真实长片，不仅使用 18 秒合成图案。
- 多音轨、内嵌文本/图像字幕、本机外挂 SRT/ASS、含/不含章节、无音轨、非标准宽高比；AAC、AC-3/E-AC-3、DTS 按实际库构建分别报告结果，不用视频解码成功代替音频验收，也不笼统写“全格式”。
- 首帧、暂停时钟稳定、seek 后位置接近目标、真实音频输出和同步、结束/切源/关闭；UI 截图与运行信息应对应同一次会话，不能用“加载成功”证明完整播放。
- 展开→实时小视频底栏→浏览列表/详情/设置→恢复→全屏→退出/收起的连续链路：session ID、轨道与暂停意图保持，位置连续推进（暂停时稳定），普通切换不重新 `loadfile`；小视频实际帧持续变化而非静态缩略图，没有双重声音或重复已开始事件，默认关闭时没有进度持久写入。
- 小视频缩放、DPI/窗口变化和快速收起/恢复后仍在自己的布局插槽中，原比例显示，字幕不侵入控件；弹窗、图片预览等遮挡层打开时正确避让，关闭后恢复同一会话实时画面。
- 底栏出现/消失后列表锚点、详情返回和草稿保持；底部内容与保存按钮仍可达；收起状态的 Space/方向键不穿透搜索、表单或弹层。系统后退/返回手势先收起展开面，不多退一个业务页面。
- 缩放、DPI/显示器切换、全屏往返、面板与快捷键焦点；视频不盖按钮，字幕不被控制条遮挡。
- 长片持续播放以及扫描/刮削并行时的响应、资源释放和内存趋势。4K/高帧率样本作为单独能力测量，失败不得用软件回退成功或满屏渲染区尺寸冒充硬解验收。
- 首版以 SDR 输出为基线，颜色和字幕显示应正确；HEVC Main10 不等于 HDR 验收。HDR 素材的 SDR 色调映射须另测，未通过不列入支持清单；原生 HDR/杜比视界输出不作首版承诺。
- 资源修订、恢复换库、凭据撤销和记录关闭的普通边界回归；压力、广泛故障注入不在首轮计划中。

当前增加了 macOS arm64 真实应用的合成素材与 loopback 原文件证据，范围见上方进展；不是全部音轨/字幕或完整平台验收。macOS x64、Windows/Linux、分发、真实长片、人工音画及 HDR 等均不能标成通过。早期独立宿主的证据边界见 [原型记录](LIBMPV_NATIVE_RENDER_PROTOTYPE.md)。

## 10. 已确认决策与剩余细化

已确认：Plex 式应用内播放与底栏收起、底栏实时小视频、续播默认关闭、三平台同时发布、Linux 首版 X11／XWayland（原生 Wayland 后续补齐）、Javdex 采用 GPL-3.0-or-later。这些不再作为开放问题，也不能被实现便利性静默推翻。

收起形态已确定为实时小视频加操作栏，不再保留“仅声音”的首版分支。全屏自动隐藏采用产品目标与 S0 技术关口区分，若不能实现需再次展示证据并确认取舍，不直接回退固定底栏。

用户后续已授权按本方案实施，并追加 Windows 实际验收；不自动授权发布或创建外部工单。单会话、失败不自动换源、实际开始才触发已启用的稍后观看移除，以及暂缓直链/队列/PiP/截图的边界保持。第 9 节的三平台共同发布关口是后续要求，不冒充当前已完成事项。

1. 返回协调剩余验收：现代 macOS 双指手势、物理鼠标返回键、图片／插件与播放的完整手工共存矩阵。共享所有者、基本快捷键和设置草稿保护已接入，最小窗口的续播选择底栏已有真实应用布局/暂停回归，不重复作为未实现项；不从 legacy swipe 或纯状态机测试推断设备输入验收。
