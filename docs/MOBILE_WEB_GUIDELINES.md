# 移动端 Web 开发规范

适用于 `src/web`，配合 [UI 设计规范](UI_DESIGN_GUIDELINES.md) 和 [路由设计](ROUTING_DESIGN.md)。保持媒体库工具的紧凑风格，以触控可用性优先，不照搬桌面侧栏。

## 实现约束

- 触屏常用按钮、图标按钮、选择器与年份输入框的有效点击区域至少 48×48 CSS px；文字可保持紧凑。检查计算后的尺寸，不能仅检查 CSS 声明。复选框可通过可点击的整行 label 扩大区域。
- `:hover` 视觉仅在 `(hover: hover) and (pointer: fine)` 下启用。触屏使用 `:active`，关闭原生 tap 高亮后必须保留按压反馈与 `:focus-visible`。
- 焦点高亮使用强调色贴合控件边缘，不使用外扩留缝的双层框。输入框、选择器与键盘聚焦按钮共用边框加 1px ring；搜索组合框只由外容器绘制高亮，内部按钮使用内描边区分键盘焦点。链接和复选框保留贴边焦点轮廓，聚焦不得改变布局尺寸。
- 触屏输入框与选择器使用至少 16px 字号；卡片标题至少 14px，资源说明与影片辅助信息至少 12px。禁止通过禁用页面缩放解决布局问题。
- 搜索使用 `type="search"`、`enterKeyHint="search"`，关闭自动首字母大写和拼写纠正；触屏提交后收起键盘。登录不自动抢焦点，保留密码管理器自动填充。
- 键盘或遥控器操作单行输入框时，有内容时左右键保留光标编辑，内容为空时左右键也参与焦点导航；上下键移向对应方向的可用控件；不拦截输入法组合输入或修饰键。多行编辑与原生选择器保留原生方向键行为；播放器左右键保留进度控制，上下键移动焦点并阻止音量变化；导航跳过隐藏、禁用及不可交互控件。
- 方向键先遵守页面区域再计算距离：主内容与侧栏之间不通过上下键斜向跳转，使用左右键跨列；上下键可连接各自上方的公共顶栏。当前方向没有目标时保持焦点，不通过页面滚动代替焦点移动。
- 网格、演员区、资源按钮、排序和分页标记为独立导航组。组内优先：左右只选同一视觉行的相邻控件，不跨行回绕；上下先选相邻行，再选最接近原列的控件，不因最后一行缺列而跨过该行。组内到边界后再找同区域的相邻组，最后才跨允许的区域边界。
- 同行控件高度不一致时，不将其当作上下方向的邻居；左右不跳进顶栏或下一段内容。侧栏与内容区左右往返记住各自离开的控件，目标隐藏、卸载或禁用时重新选择可用目标。跳转内容的辅助链接保留在 Tab 顺序中，不参与几何方向键选点。
- 页面尚无控件焦点时，首次方向键从文档顺序中的第一个可用控件开始，不以整个 body 的几何中心计算目标。
- 每个影片网格只保留一个 Tab 入口，并随方向键或鼠标聚焦更新到最近使用的卡片。Tab/Shift+Tab 用于进出网格，网格内部使用方向键；方向导航仍允许到达网格内 tabindex=-1 的卡片。上下跨组优先最近的视觉行，不因目标较宽而越过播放器。
- 非编辑状态按 `/` 直达搜索并选中已有搜索词；详情非编辑状态按 Esc 返回来源。播放器第一次 Esc 退出播放器焦点，全屏及原生选择器优先保留系统退出行为。
- 页面切换的焦点落在可操作控件，不聚焦标题或纯内容容器：详情进入时聚焦顶部返回按钮；翻页、演员筛选等结果变化加载成功移向首张卡片，失败移向重试按钮，空结果返回搜索框。用户在等待期间主动移走焦点时不抢回。删除最后一个筛选回到首页可用控件，普通详情返回恢复来源卡片，来源失效时回退到可用控件；跳到内容的辅助链接也遵守此规则。
- 浏览范围使用按钮打开模态选择列表；打开前方向键只移动焦点，打开后方向键只移动选项焦点，Enter/Space 确认才切换范围，Esc 取消并恢复入口焦点。Tab/Shift+Tab 在弹层内循环，搜索快捷键和详情返回不得穿透弹层。播放器非全屏状态按 Esc 返回详情的返回按钮，全屏时让浏览器先退出全屏。Tab/Shift+Tab 始终保留原生遍历，不劫持播放器左右键或选项列表方向键；全屏时不将焦点移到全屏区域之外。
- 小屏媒体库和清单使用分组选择弹层；保留当前选择及数量，桌面继续使用侧栏。选择后更新现有 URL 路由，不另建一套筛选状态。
- 顶栏高度随内容增长，处理顶部及左右安全区；正文、登录与播放器避免刘海和系统手势区域遮挡。页面使用动态视口高度，固定区域不能遮挡焦点。
- 进入详情页默认加载主资源并暂停。初始焦点保持在顶部可见区域，不自动聚焦播放器下方标题。返回按钮与浏览器后退均恢复原列表滚动位置，切换筛选不套用旧列表位置。
- 不可播放原因直接显示，不依赖 title 或 hover。配对倒计时不放入 live region；只播报等待、批准、过期等状态变化。
- 封面只读取 cover，按 7:10 从右侧裁剪；背景与封面职责分离。保持图片懒加载和固定比例，避免加载后布局跳动。
- 详情页不单独展示封面；无可播放资源或播放失败时，在播放器位置以横版区域完整显示封面，不裁剪，点击封面本身可预览，不另设“查看封面”按钮。剧照通过按需加载的图片预览器展示完整原图，适配横竖图和安全区。支持键盘切图、缩放、触屏滑动与双指缩放；预览期间隔离页面快捷键和背景滚动，关闭后恢复入口焦点及滚动位置。预览控件至少 48px，图片失败仍能关闭或切图。

## 验收

图片预览打开时加入同 URL 的历史记录；浏览器或系统返回先关闭预览，保留详情页。关闭按钮、Esc 同样退回这条记录，避免下次返回多出空步骤；关闭后恢复图片入口焦点和滚动位置。

自动浏览器验证至少覆盖 320×844、390×844、844×390 触控及 1280×800 桌面：无页面横向溢出；点击区域、输入字号、范围弹层的确认、取消与焦点约束、搜索提交、详情初始位置、返回恢复正确。使用普通模拟影片数据，不依赖个人媒体库。

运行 `npm run web:check:mobile`（需要 Chrome 和 FFmpeg，可通过 `JAVDEX_BROWSER_CHANNEL` 选择其他 Playwright Chromium channel）。脚本生成普通色块测试视频，读取后删除临时目录；模拟接口支持 Range，避免把无法跳转的测试流误判为进度键失效。完成后关闭浏览器及本机服务。

`scripts/web-keyboard-journey.mjs` 通过真实键盘事件完成搜索、方向导航、进入详情、空格播放/暂停、左右进度、演员筛选、年份、翻页与返回；不得用 locator.focus/click/fill 绕过导航。登录流程同样用 Tab、文字输入、Space 和 Enter 完成。DOM 查询只用于观察和断言。

本轮验证：上述四种视口的浏览、选择范围、搜索、默认暂停与两种返回路径通过。真机软键盘、屏幕安全区、系统字体放大和读屏尚未执行。

真机验收另行覆盖 iOS Safari 与 Android Chrome：键盘打开/收起、输入聚焦缩放、横屏安全区、系统字体放大、读屏状态播报、原生视频控制。桌面浏览器模拟通过不等于真机通过；记录未执行项目。

## 依据

- [W3C WCAG 2.2 目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)：AA 最低尺寸通常为 24×24，并存在间距等例外；本项目的 48px 是触控体验目标。
- [Google 触控目标](https://web.dev/articles/accessible-tap-targets)与[输入方式适配](https://web.dev/learn/design/interaction)。
- [MDN enterkeyhint](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/enterkeyhint)。
- [WebKit 安全区](https://webkit.org/blog/7929/designing-websites-for-iphone-x/)与[W3C 焦点不被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)。
