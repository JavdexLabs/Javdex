# NFO 导出界面优化方案

状态：首轮方案已实现（2026-09-05）。

已复用 `AppFormField + SelectControl`，收敛配置与统计布局，将操作放在预览之后；提示、文件明细和完成报告按需挂载，每页最多 50 条。文件类型与执行结果使用穷尽中文映射。保留既有导出任务与计划生命周期，不新增依赖或数据合同。

通过隔离 Electron 窗口验证真实组件的深浅主题、420px 窄窗口、长媒体库名、空导出、下拉菜单键盘选择、修改选项释放旧计划、749 条提示分页，以及终止任务和关闭报告。视觉检查使用模拟数据，不连接用户媒体库。

## 依据与问题

依据用户提供的 NFO 导出截图，以及 `UI_DESIGN_GUIDELINES.md`、`UI_COMPONENT_CONTRACTS.md`、媒体库设置页和当前 NFO 导出组件。

- `NfoExportPanel.tsx` 的两个下拉框直接使用原生 `select`；软件已有 `SelectControl`，媒体库设置页已通过 `AppFormField + SelectControl` 统一触发器、菜单、主题和键盘操作。
- `.optionGrid` 的两列默认 stretch，`.control` 又是自动行高的 grid；左侧存在说明行，右侧只有标签和选择框，造成右侧行高分配异常。说明文案不应决定控件高度。
- 单个媒体库占用一个完整 fieldset，大量边框和十个同权重统计块挤占视觉空间。
- `preview.warnings.map` 默认展开全部提示，截图中的 749 条提示成为整页主体；真正的文件预览入口反而被推到很远的位置。
- 开始执行按钮位于预览之前，阅读顺序没有体现“确认范围与影响，再执行”。
- 文案包含 Profile、fanart、锚点、写入项以及原始 `kind/action/disposition`，偏向实现术语。

## 推荐布局

保持现有存储设置中的单个 `SettingsCard`，内部依次为：

1. 标题及一行用途说明：“将影片资料与图片导出到视频所在目录”。
2. 导出媒体库：单库显示紧凑选择行；多库使用可换行、限制高度的复选列表，保留未选任何库的状态与校验。
3. 两列配置：“兼容格式”和“已有文件”，控件顶部对齐，格式说明独立放在下一行。
4. “附带图片”紧凑复选行：影片封面、详情背景、样张、演员头像。
5. 导出预览：主要显示待写入文件数和预计体积；影片数、资源数、新建、覆盖等以次级文字行显示。零值保持安静，冲突与不可用为非零时明显提示。
6. 可展开的提示与文件明细；主操作放在预览后的底部，左侧交代写入位置和覆盖策略，右侧“重新预览 / 导出 N 个文件”。

初始没有预览时，显示“预览导出”；选项变化后保留现有计划失效和 lease 释放逻辑，要求重新预览，不能执行旧计划。导出中的全应用阻塞、终止与完成报告行为保持现有合同。

窄宽度下配置改为单列，底部动作允许换行。使用项目密度和语义 token，不按截图像素直接缩放字号。

## 控件与样式复用

- 两个下拉框替换为 `SelectControl`，字段外壳采用 `AppFormField`，保留明确的 label/id 或 aria-label。
- `.optionGrid` 使用 `align-items: start`；字段内容按自然高度排布。控制高度来自软件通用 control token，删除本页自制的 `.select` 外观。
- 保留 `SettingsCard` 和 `Button`；以留白与分隔线组织配置、预览和操作，取消十个独立统计卡片。
- 多选项保留 checkbox 语义，采用软件现有尺寸、accent 和 focus token，整行可点击。仓库没有独立通用 Checkbox 组件，不为本页另造组件框架，也不把一次性导出选项改成表示即时生效的开关。
- 提示和文件明细限制内部高度，预留滚动槽；使用可复制文本、稳定列宽和中文状态。

## 提示处理

第一轮只调整呈现，复用当前数据合同：

- 常驻显示总提示数，详细列表默认折叠；展开后在有界区域内滚动，必要时分页，避免一次挂载数百条。
- 新建、覆盖、跳过、冲突、不可用属于不同文件结果，分别展示；不能把提示总数表述为失败数。
- 冲突与不可用数量始终可见，缺背景和格式不支持字段等提示不应呈现为整片高饱和警报。
- `NfoExportFileKind`、`NfoExportPlanAction`、`NfoExportResultDisposition` 在前端建立穷尽中文映射；不改变底层枚举。
- 对于主进程返回的现有提示字符串，第一轮保留原始文本，不在 renderer 中通过中文正则反推类别。

若后续确实需要“按原因聚合、每类影响多少影片”，再将 warning 扩展为 `{ code, videoCode?, message }` 之类的窄结构并明确计数单位。只影响本模块主进程输出和共享类型，不建设通用通知平台，不持久化新状态。

## 范围、替代方案与验证

推荐先交付控件、布局、折叠提示、中文状态和阅读顺序调整，主要修改 `NfoExportPanel.tsx` 及其 CSS Module。适当提取预览与结果展示，避免进一步增加顶层任务状态逻辑；不新增依赖、不改数据库。

仅替换 select 成本最低，但解决不了长日志和统计层级。拆成独立导出向导能隔离任务，却增加页面和导航状态，目前没有必要。紧凑双列适合现有桌面设置页，纵向单列作为窄屏布局即可。

验证重点：

- 用现有交互测试确认选项变化使计划失效、重新预览、执行、终止及释放 lease；增加一条大量提示默认折叠的行为验证。
- 手动检查两个下拉框的方向键、Enter、Escape、焦点返回和菜单是否被容器裁切。
- 检查单库、多库、长库名、长格式说明、大量提示、零可写文件和非零覆盖/冲突等状态。
- 在实际 Electron 窗口检查深浅主题及不同宽度，避免只用 CSS 字符串断言代替视觉检查。

交互布局示意使用截图中的 383 部影片、385 个资源、788 个文件、749 条提示与 64.0 MiB；提示明细与文件行只展示少量示例，不代表重新读取了用户数据库。

## 第二轮评估：用途、默认选择与结果理解

状态：已实现（2026-09-05）。本节依据新增封面裁剪、样张备份和演员头像兼容说明后的界面及组件代码，记录第二轮调整的依据与范围。

### 核心问题

控件已统一，但补充说明重新挤占了主体。首次使用者仍需要自行推断 NFO 是什么、哪些内容必定导出、文件写到哪里，以及预览数字与实际操作的关系。应调整信息层级，保留现有设置卡片和一次预览、一次执行的流程。

截图中的“文件 156、待写入 122、跳过 34、样张 122”口径不同。样张总数不代表此次写入样张数，不能仅凭这些合计推断本次只导出了样张。预览应从计划文件的类型和动作共同计算实际写入组成。

### 推荐信息结构

1. 标题改为“导出影片资料（NFO）”。用途说明：“将已有影片资料和图片保存到视频旁，供支持本地资料的播放器读取。”下方一条次要说明：“一次性导出，不自动同步。”避免在标题和底部重复介绍目的。
2. 保留“媒体库”多选；未选择时明确提示“先选择要导出的媒体库”，预览按钮禁用。不要自动勾选所有媒体库。
3. “兼容格式”改为“目标软件”，仍沿用现有选项和映射，不额外创建软件预设系统。通用选项补充“不确定时可先选通用 / Kodi”；具体兼容限制紧邻该字段展示一行，完整解释折叠。此处不能暗示所有软件完整支持 NFO 或每一种图片。
4. “已有文件”保留双列布局，选项用“保留已有文件（推荐） / 覆盖同名文件”。覆盖只针对计划内文件。选中覆盖后，在预览中显示实际覆盖数量，不新增重复确认弹窗。
5. “导出内容”先以普通说明列出“影片资料（NFO）始终导出”，包括演员名单；不用不可点击的勾选框表达必选项。常用图片保留“影片封面 / 详情背景”，默认选中。
6. “更多图片”折叠容纳“样张备份 / 演员头像”，默认关闭的是选项本身，不重置已有保存的选择。折叠标题显示已选附件名称或数量，避免隐藏生效的选项。样张注明“供 Javdex 备份与回读”；头像注明适用范围，未验证的目标软件仍显示简短限制，不能只放悬浮提示。
7. “导出说明与文件示例”提供按需阅读的技术细节：横版保留原图并右侧裁剪 2:3 海报、竖版仅导出海报、样张备份目录、演员头像目录及各格式限制。示例按当前格式生成或明确标为示例，不把一种软件的命名规则写成全部软件通用规则。
8. 预览下方保留主操作，不新增向导、路由或独立任务页面。

结构示意（数字沿用截图，仅表示层级；实际写入组成必须由计划计算）：

对于 STRM，实际位置为对应 STRM 文件旁；没有本地视频或 STRM 的影片不能导出，应在预览注明跳过数量。位置说明准确反映现有规则，不增加无实际支持的输出目录选择器。

### 预览与任务反馈

- 优先呈现影片范围、待写入数量和体积，再显示“新建 / 覆盖 / 保留已有”；零值不占主统计行。资源数和文件总数放进明细，不与本次写入并列竞争。
- 本次写入的类型统计只包含新建、覆盖动作；使用“影片资料、竖版海报、横版封面、背景、样张备份、头像”等现有中文类型。若 NFO 和封面都保留，仅写入附件，应明确显示这次只补充哪些附件。
- “导出提示”不是失败数。冲突、不可用等阻止对应文件写入的结果仍常驻显示，其他可写文件正常执行。继续复用现有警告字符串，不在前端解析中文实现伪分类。
- 修改设置后显示“设置已更改，请重新预览”，继续释放旧计划，不能执行失效计划。初始状态把“预览导出”作为主按钮，已预览状态把导出作为主按钮。
- 全部跳过时显示“无需写入，已有文件已保留”。用户要更新旧资料或旧海报时，提示选择覆盖并重新预览；不能自动切换覆盖策略。
- 完成报告根据结果区分“导出完成 / 部分完成 / 已停止 / 未写入文件”，不能统一显示完成。仅在确实写入后提示到目标软件刷新本地资料或图片，保留失败明细及原因。关闭按钮简化为“完成”。
- 当前终止任务异常写入页面级 `error`，错误位于阻塞弹窗后方；实施时改为在任务弹窗内展示并允许重试。补查 Tab 焦点循环和关闭后的焦点返回。

### 视觉边界与实现范围

沿用 `SettingsCard`、`AppFormField`、`SelectControl`、`Button` 和语义 token。主要调整分组、说明位置、统计口径与状态文案；不新增依赖、数据库字段或通用配置框架。

按现有设置页 token 使用标题 14、正文 13、次要说明 12 的层级和 36 高控件；截图缩放不作为尺寸依据。用间距和细分隔线区分区域，避免额外彩色图标、统计卡片、多层边框和常驻大段警告。窄屏继续双列变单列，媒体库长名称和附件说明允许换行。

第一批落地包括信息结构、更多图片折叠、实际写入组成、空状态和完成状态，以及弹窗内终止错误。警告按原因聚合留待确有需求时扩展窄结构，不作为本轮前置条件。

验证集中在：未选媒体库、保存的附件选择仍可见、修改设置使预览失效、只有附件写入、零写入、覆盖计数、部分失败与终止失败可见、键盘焦点、深浅主题和窄窗口。只为关键状态行为补充必要验证，不增加文案和 CSS 字符串快照测试。

实施验证：组件测试 9 项通过，前端类型检查、定向 ESLint / Stylelint 和应用构建通过。使用实际 React 组件与全局样式，在隔离的 Chromium 页面中验证深浅主题、420px 窄窗口、附件折叠与已选摘要、选项变更释放预览、未选媒体库禁用预览、键盘选择目标软件、停止失败后重试、任务弹窗 Tab 循环及关闭后返回预览按钮。页面使用模拟 API 与计划数据，没有读取或写入用户媒体库；这不代替播放器兼容验证。
