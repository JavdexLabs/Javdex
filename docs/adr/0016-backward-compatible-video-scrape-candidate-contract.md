# 向后兼容地扩展影片刮削候选合同

影片插件可以返回单个详情结果、详情结果数组或未找到；主程序把旧式单结果统一视为单元素候选集合，空数组与 `null` 都视为未找到。数组中的每项必须来自搜索结果第一页、番号完全匹配且已抓取详情；主程序仍会严格复核番号，排除不匹配项并记录警告，返回结构无效或任何完全匹配详情抓取失败都会使整次刮削报错，不允许用模糊结果、未完整抓取的候选集合或第二页结果补位。同一来源中，规范化 `sourceUrl` 相同的条目视为同一候选并只保留首次出现项；影片业务身份相同但详情 URL 不同的候选仍全部保留，缺少 `sourceUrl` 时不猜测去重。实践中无法获得有价值的稳定外部 ID，因此合同不新增该字段；数据库迁移移除现有但始终为空的 `external_id`，并将其所在表由 `video_external_ids` 改名为表达站点来源语义的 `video_sources`。该联合合同保留现有用户插件兼容性，同时让新插件完整表达同番号的多个发行候选。

候选去重使用保守 URL 规范化：仅接受 HTTP/HTTPS，采用标准 URL 语法、规范主机名和默认端口并移除 fragment，但保留协议、路径、查询参数及其顺序，不删除追踪参数，也不擅自等价有无尾斜杠。

插件必须成功抓取第一页全部番号完全匹配详情后才能返回候选集合；任一详情失败使整次刮削失败，不接受其余详情组成的不完整集合。候选图片下载失败仍沿用普通影片刮削的保留与警告行为，不把资源失败提升为详情匹配失败。

`supportedFields` 继续作为插件结果的信任边界：候选比较与暂存会包含插件已声明且通过校验的全部字段和资源，不受用户本次勾选字段限制；未声明字段一律不展示、不暂存，也不应用。
