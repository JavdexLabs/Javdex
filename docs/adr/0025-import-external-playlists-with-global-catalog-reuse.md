# 用独立 Agent 原子导入外部清单并复用全局影片目录

外部清单导入使用独立的 `playlist-importer` 用例和 `PlaylistImportModule`，统一支持新建清单与追加到已有清单。导入是单一前台 Session：弹窗在运行期间不能转入后台，软件退出、主进程终止或浏览器会话丢失后本次导入作废，不提供跨重启恢复。任务把全部清单页和有限虚拟滚动窗口记录到当前 SQLite 连接的 TEMP 表，枚举完成后才读取必要的影片详情；全部影片身份确定后，在单个 SQLite 事务中按任务冻结的写入选项创建或复用影片、保存详情相关链接并写入清单。Agent 只能提交页面和身份证据，不能直接修改影片、媒体库或清单。“自动创建无资源影片”和“保存详情页到相关链接”默认开启，关闭后分别跳过自动新建条目或不写入详情链接；“保存来源清单链接”默认关闭，开启后把外部清单 URL 去重追加到目标清单的相关链接。

新清单名称留空时，Agent 在首个清单页检查点中只能根据明确页面证据提交名称建议；不能根据影片内容、URL 或用户名编造。最终原子应用依次使用用户输入、Agent 名称建议和原有的“域名 · 日期”兜底。

影片候选在全局目录中按永久影片 ID 去重。唯一规范化番号完全匹配是本导入用例的快速复用策略，不是全局影片唯一性约束；多个同番号影片必须用详情强信号进一步匹配。强信号仍无法唯一选择时，目标媒体库只在恰好包含一个合理候选时作为决胜偏好，否则交给用户。复用其它媒体库影片不会迁移或复制成员关系；目标媒体库仅承接新建的无资源影片。

清单是全局对象，可以引用跨媒体库影片或没有媒体库成员的影片。因此清单读取不按活动媒体库过滤，而且只要任一清单仍引用影片，自动的无资源成员清理和全局无资源影片清理都必须保留它。用户显式移除成员、清单引用或影片仍按原有权限执行。

页面检查点、分页 frontier、滚动批次、候选和身份决策只存在于当前连接的 TEMP Session 表中，不进入发布数据库 schema。网络超时或来源变化只允许在同一活跃 Session 内从当前未封存页面起点重试，不重放退出前的滚动窗口。最终影片、媒体库成员关系、相关链接和清单关系仍通过单个 SQLite 事务原子写入。这样保留页面级完整性和最终原子性，同时避免为未发布的 0.6.0 引入跨重启恢复、专用持久化暂存表和产品重试日志。
