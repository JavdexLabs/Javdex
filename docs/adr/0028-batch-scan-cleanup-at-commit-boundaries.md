# 在提交边界分批执行扫描清理

大库扫描在文件处理结束后仍会同步核对待确认记录、清除缺失资源、执行延迟目录清理及移除无资源成员。把这些操作放在主线程的一个长事务中，不能在处理中响应界面和取消；只把读取分页也不能解除整段阻塞。

生产清理改为可让出主循环的短事务批次。每批的业务写入与审计仍在同一事务提交，提交后才累计结果。事务和 SQLite 游标均不得跨异步等待；继续下一批前检查取消，并在写入时复核记录、成员保护条件和根目录身份。扫描文件阶段失败或取消时仍不进入清理。

这细化了 ADR-0014 的取消和失败合同：**清理开始后**取消或失败，保留此前已提交批次及其审计，回滚当前失败批次，停止后续清理，并将本次扫描标记为取消或失败。不能将部分完成报告为成功或零变更，也不能通过重放审计重复累计。下一次扫描根据仍存在的记录重新核对，已完成的删除不重复执行。

延迟目录任务只有在其资源和待确认记录都清理完成后，才能关闭任务并将根目录改为停用。同一影片跨本次全部待移除根目录的资源及其主资源选择在一个事务中提交，不能提升稍后就会删除的资源；单影片超出页大小时保留其原子性。无资源成员清理仍保护固定成员和播放列表引用，且不删除全局影片资料。

异常退出沿用扫描审计的恢复规则：启动时将中断任务标记为失败，保留已提交业务数据及审计条目；未发布的审计不自动包装成一次完整成功扫描。这里不引入跨重启继续同一个扫描的保证。

短事务减少累计工作引起的主线程停顿，但单次 SQL、目录身份检查或文件系统调用仍可能很慢；批次记录上限不等于硬性的毫秒期限。只读目录 worker 也不替代这些写入边界。
