# ADR-0030：使用检查点恢复与按用途模型配置

- 状态：Accepted
- 日期：2026-09-20
- 依据：用户接受取消历史冷恢复、合并 Profile/虚拟 Route、将低价值模型调参收为内部策略的组合。
- 替代：ADR-0020 中冷 rebuild、独立 Profile/虚拟 Route 和用户配置缓存/压缩预算的部分；其余工具治理、Pi 运行时所有权和提交屏障不变。
- 同时替代 ADR-0022 中 schema v2、用途可配置缓存/压缩参数及内部 Profile 投影的部分；用途绑定仍是唯一模型配置源。

## 决策

1. 只通过 Pi 保存的会话检查点恢复运行。检查点损坏或不兼容时明确拒绝继续，提示新建任务，不从历史重新构造对话，不重放最后命令或工具。
2. 保留产品日志、审批、工具副作用 ledger、业务回执及已有成果。新观察不再生成和保存 RuntimeRecoveryFrame；旧表和旧历史数据保留，避免改写已发布数据库迁移。插件恢复失败的工作区不随离开页面自动清理，用户仍可显式清除。
3. AgentConfiguration 按明确 definition ID 读取用途配置。工具包、授权和审批条件形成代码所有的 AgentPolicy；不包含模型路由、用户可选 Profile 身份或压缩参数。角色仍用于调用语义及缓存隔离，不再对应虚拟路由配置。
4. 保留连接、模型、应用默认模型和用途覆盖。插件开发独立配置；资料采集、清单导入和媒体库整理共用既有整理用途。缺少模型或能力时仍拒绝，不能偷偷换用其他模型。
5. 新任务自动启用 Pi 压缩。预留与最近内容各不超过有效上下文的四分之一，并分别以 16,384/20,000 token 为上限。缓存在模型明确支持时使用 short，否则 none；不自动请求长期缓存。用户仍可选择思考强度、输出上限、超时、任务轮次和上下文上限，自定义模型能力覆盖保留。
6. 模型配置 schema v2 一次性迁为 v3，只删除用途中的 cacheRetention/compaction，保留连接、模型引用、其他参数和凭据引用。完整校验后原子写入，写入失败不把迁移结果缓存为成功。
7. 已有运行的模型和运行设置仍从冻结快照恢复，包括原缓存保留和压缩设置；旧 profile 快照只提取工具权限，其他冻结字段不重算。新任务才使用新策略。

## 取舍

失去的是检查点损坏后自动找回完整对话上下文的能力，以及新任务自定义压缩/长期缓存参数的能力。保留正常重启续跑、工作成果、工具授权、业务恢复与模型选择。新任务不再为备用恢复维护第二份完整消息载荷；不承诺用历史审计重建运行时。

验证覆盖正常检查点恢复、损坏拒绝与成果保留、旧配置迁移及写入失败、旧运行快照兼容、小上下文策略、权限/审批和模型设置界面。

2026-09-20 实施验证：根类型检查、pretest、桌面/Web 构建通过；Agent/工具/插件/采集定向回归 164 项通过，补充模型迁移/旧快照及整理/清单模块回归 51 项通过（两组含重复覆盖，不相加作为独立测试总数）。真实 Electron 设置界面检查通过，真实 v2 配置文件首次启动迁为 v3、再次启动不改写的检查通过。未调用真实付费模型或重新打包发布。
