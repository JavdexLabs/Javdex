# 单容器运行外壳管理服务端发行包

## 2026-10-16：客户端版本恢复入口与移除升级备份

客户端“服务端升级”仅面向服务端落后于当前客户端的恢复场景，在线发现固定访问此客户端版本的 Release tag（含预发布），离线上传、准备和安装均重新核对同一目标。不提供旧管理器兼容分支或独立更新授权。

用户决定移除与现有备份功能重复的升级备份，避免大资料库、图片和嵌套备份的复制占用。在线、离线及镜像启动升级均不创建快照，不估算或预留整库容量；备份统一由现有“备份与恢复”功能承担，界面提示先用与当前服务端版本一致的客户端备份重要资料。停止阶段且资料未变时仅恢复原服务运行；安装/验证失败及中断转为维护状态和人工恢复，提交后只继续激活。成功后仅清理程序发行和任务，不轮换手动备份。此决策取代下文关于强制停机快照、升级备份及自动资料回退的条款。

用户确认只部署一个容器。采用常驻管理父进程监督非 root 业务子进程，通过签名的完整服务端发行包、持久版本目录和停机数据快照实现在线/离线更新；不安装宿主机助手、不挂载 Docker socket、不使用 Docker-in-Docker，也不让业务进程覆盖自身代码。此前未发布的 Docker 镜像更新执行器由该方案替代，不并行维护两套托管更新机制。

程序、查询 worker、Web 与对应 Linux 架构原生依赖作为一个发行单位；业务版本与运行外壳版本分离，固定在镜像中的管理器、Node 与系统环境仍通过替换镜像维护。数据迁移后验证、提交前恢复和提交后不覆盖新写入的原则保留。该取舍减少用户部署与宿主机权限负担，代价是增加进程监督、发行目录完整性及运行环境兼容验证；不是不停机热更新，也不把同容器进程隔离宣称为安全沙箱。

## 2026-10-15：镜像启动时升级业务

用户确认更换镜像也应带来对应业务升级。同运行环境内按 SemVer 比较镜像种子与当前发行，仅较新版本进入既有停机备份、安装、验证、持久提交与恢复事务；同版本和较旧种子不覆盖程序卷。信任来自管理员所选镜像，逐文件与原生闭包校验仍执行，不伪造签名清单、不开放未经签名的远程安装入口。下载和上传路径继续要求官方 Ed25519 签名。

安装记录显式区分镜像身份与签名包；本地持久摘要记录每个镜像发行的自动尝试，避免重启循环。保留管理员已上传/准备的更新，不自动抢占。首次空程序卷初始化不属于这项托管升级，已有旧资料须事先人工备份。此决策不引入额外联网发现，也不改变容器运行环境跨代迁移要求。

## 2026-10-15：统一地址与一次配对

新 Compose 通过 `JAVDEX_PUBLIC_URL` 启用常驻 HTTPS 网关；业务子进程仅监听容器回环，更新停服期间管理入口仍存活。网关覆盖转发头、传递真实对端，业务仅接受带进程级随机凭据的回环转发；转发请求不能使用部署侧恢复接口，网页 Cookie、writer 和更新 token 仍分离。未启用新配置的旧双端口部署保持原行为。

部署侧 `pair` / `pair-recover` 发放十分钟一次性配对信息，客户端同时保存统一地址、固定证书及两类授权。候选 writer 在领取前持久化，依赖既有 writer 事务回执支持丢响应重试；显式恢复才允许接管已有 writer。客户端只在固定证书校验后发送凭据，禁止跨 origin 和重定向。播放器使用受限回环流桥接访问授权媒体，固定服务端证书，不向播放器泄露管理凭据，不进行转码。浏览器仍需单独信任证书，统一入口不等于开放公网。

## 2026-10-15：移除双端口兼容

用户明确要求只保留一个入口。本决策取代上节保留旧双端口行为的条款：`JAVDEX_PUBLIC_URL` 现在必填，必须为 HTTPS 根地址；缺失或仍配置 `JAVDEX_UPDATE_PUBLIC_URL`、`JAVDEX_UPDATE_PORT`、`JAVDEX_UPDATE_LISTEN_HOST` 时拒绝启动。业务、网页、播放、配对和更新共用公开网关，内部业务只绑定回环，不对外发布。

只保留 `start`、`pair`、`pair-recover` 管理命令与统一可信设备授权，移除独立更新 token、独立更新配对和桌面裸令牌输入。旧本机独立配对凭据不再加载；部署者调整配置并重新配对，保留原数据卷与程序卷。手动连接仍允许当前 HTTPS 地址的自签名证书，已保存的证书固定校验保持有效。此变更不改变 schema，也不把内部 writer 事务或回环 HTTP 当作另一个公开入口。

## 2026-10-15：手动令牌连接与证书信任

用户进一步要求仅保留手动连接，并明确合法公开证书无需变更确认。本决策替代上文的配对 JSON 和双授权命令：公开管理命令仅为 `start` 与 `token`，后者只输出十分钟一次性令牌；根据当前资料库自动选择首次授权或新增设备，不撤销已有设备。遗失设备可在新授权电脑上逐台撤销，不再提供 `pair-recover` 命令。

桌面仅填写 HTTPS 地址和一次性令牌。首次自动接受并保存证书；合法公开证书继续进行系统信任、有效期与主机名校验，续期或变化自动接受。自签名证书指纹变化时暂停连接，在发送 HTTP 凭据前展示新旧指纹并要求用户确认；拒绝保留旧信任。证书信任按 origin 独立保存，与设备凭据分离，业务、图片、播放和更新共用此规则。
