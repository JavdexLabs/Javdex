# 同一资料库的多可信桌面设备

用户确认首版为同一资料库、多台可信电脑、相同管理权限。每台电脑独立配对并保存自己的凭据；新增设备不替换已有设备。此决策扩展 ADR-0029 的桌面远程模式，并替代单 writer 接管模型作为普通新增电脑的流程。网页仍为独立只读会话；不引入账号、角色、个人收藏或资料同步。

schema 21 将管理凭据主键改为稳定 claimId，增加设备名称，允许同一授权代次持有多个有效凭据，保留 schema 20 的原管理凭据。`deviceAdd` 为新增授权，普通 `pair` 按资料库是否认主选择首次或新增。部署恢复和显式 handoff 仍撤销全部旧设备；新增不提升代次，也不撤销播放。

可信设备列表不返回凭据；其他可信电脑可以单独撤销设备，当前电脑不能自行撤销。撤销提升资料库共享写入代次，阻止先前已认证、尚未提交的请求；其他设备凭据仍有效，客户端验证新代次后最多重试一次。既有实体版本与 operationId 回执继续阻止陈旧覆盖和重复提交。维护与异步文件操作未完成时拒绝撤销。

播放授权记录签发设备；撤销只关闭该设备及无归属旧授权的流，其他设备授权更新代次继续使用。更新管理器从当前已验证发行的 SQLite 驱动只读查询设备凭据，每次检查重新打开数据库，兼容停服与恢复时文件替换。统一入口的更新授权与设备管理凭据一致，因此单设备撤销也撤销其更新权限；版本独立的更新协议保留。独立更新 token 的历史兼容由 [ADR-0031 的移除双端口决策](0031-manage-server-releases-inside-one-container.md#2026-10-15移除双端口兼容)取代。

部署端 `pair-recover` 在完成新领取时才撤销全部旧授权。已发起的升级属于服务端持久任务，撤销其发起设备不会取消该任务。数据库升级后回退须使用升级前备份及匹配程序。

统一配对的设备身份绑定 serverId 与证书。授权的整库恢复保留可信设备，客户端只在相同服务身份上复用设备凭据；业务认证成功后更新资料库身份，不把其他服务的旧凭据作为回退。备份任务仍归属于发起设备，撤销其他设备不改变其任务归属。

2026-10-15 补充：部署端授权命令已收敛为 `token`，遗失设备时也先新增设备，再逐台撤销旧设备。原 `pair-recover` CLI 由 [ADR-0031 的手动连接决策](0031-manage-server-releases-inside-one-container.md#2026-10-15手动令牌连接与证书信任)取代；内部恢复事务保留用于既有管理协议。
