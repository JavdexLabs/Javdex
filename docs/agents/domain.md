# 领域文档

本文件规定工程技能在探索代码库时如何读取领域文档。

## 探索前读取

- 根目录的 `CONTEXT.md`
- `docs/adr/` 中与当前工作区域相关的架构决策记录

如果这些文件尚不存在，直接继续，不提示缺失，也不预先建议创建。`domain-modeling` 等技能会在实际确定术语或架构决策时按需创建。

## 文件结构

本仓库采用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-another-decision.md
└── src/
```

## 使用领域词汇

在 Issue 标题、重构提案、假设和测试名称中，应使用 `CONTEXT.md` 定义的领域术语，避免改用其明确排除的同义词。

如果所需概念尚未出现在词汇表中，应先判断这是与项目用语不符，还是领域模型确实存在空缺；后者可交由 `domain-modeling` 处理。

## 标明与 ADR 的冲突

如果提议与现有 ADR 冲突，应明确指出，不要静默覆盖：

> 与 ADR-0007 冲突，但值得重新讨论，因为……
