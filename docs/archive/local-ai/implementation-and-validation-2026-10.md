## AI 字幕闪烁修复（2026-10-17）

此前每条译文或未来分块回填都会改写整份 ASS，并执行 `sub-reload`；mpv 会先卸载再重新添加字幕轨道，因此暂停画面仍可能闪烁。旧的串行回执和文件替换重试解决了竞争及文件占用，不能保证重载期间画面连续。

Windows、macOS 与 Linux 现在共用 `native/generatedSubtitles.h` 的时间轴解析，以及 `MpvCore` 的固定 ID ASS OSD 叠加层。原生渲染循环观察媒体时间、字幕延迟和视频显示范围，只替换当前实际显示的文字；未来字幕追加不会清空或重建当前画面。`osd-overlay` 的 ASS 事件本身不执行时间轴，由共用内核选择当前事件；命令使用具名 node 异步提交，不同步等待渲染线程。底部留白与字号按实际视频高度缩放，保留 5% 底边距。

主进程继续合并并串行提交最新文档，磁盘 ASS 仅作为临时诊断快照，原生显示直接使用内存文档，不再读取／重载该文件。字幕选择器中的 AI 条目由包装层投影，选择它时关闭 mpv 原字幕并显示叠加层；手动改选其他字幕优先，停止仅在 AI 仍持有选择时恢复原字幕。换片和销毁清空时间轴。显示错误仍只影响 AI 字幕，保留重试、缓存及 ASS／SRT 导出。Linux 私有管道增加文档修订确认，不能用过期的空闲快照提前认定更新成功。

本机 Windows x64 已重新编译原生运行库并通过共用 C++ 时间轴检查。隔离 Electron／真实 libmpv 使用暂停的合成视频：连续 20 次追加未来字幕与 20 次更新当前文本，采样均无字幕空白；前者未发送任何额外显示命令。连续播放的字幕区间内部采样匹配时间轴，另验证暂停跳转、字幕延迟、选轨／恢复、带黑边尺寸变化和换片清理。报告与重放入口为 `output/ai-subtitle-overlay-check/{report.json,run.mjs}`，不读取用户资料库或运行模型推理。这不代替真实长片实测；macOS／Linux 的原生编译与 GUI 播放仍需在对应平台验收。

本次涉及三平台原生适配接口，须使用当前源码重新构建播放运行库与桌面主进程，并完整重启应用；旧运行库明确报需更新，不退回轨道重载。下方 2026-10-16 的轨道更新流程作为历史修复记录保留。

## AI 字幕默认位置调整（2026-10-17）

生成 ASS 原来在 1080 行逻辑画布中使用 120px 底边距（约 11.1%），导致单双语字幕长期偏高。现在保持底部居中，将底边距调整为 54px（5%），双语两行作为整体从底部向上排，随视频显示尺寸等比缩放；播放显示和 ASS 导出共用该样式。

参考 [mpv 稳定版文档的字幕边距](https://mpv.io/manual/stable/#options-sub-margin-y)：默认 34 个以 720 高度为基准的缩放像素，约为 4.7%。[VLC 3.0.x 配置](https://github.com/videolan/vlc/blob/3.0.x/src/libvlc-module.c) 的 `sub-margin` 默认 0，表示不额外强制移动字幕，具体位置仍受字幕格式和样式控制；两者不能当成同一种像素单位直接比较。

本次通过实际生成的 ASS 与 FFmpeg／libass 渲染核对 1080p、720p 下的双语／仅中文／仅日语：1080p 字形整体下移 66px，720p 下移 44px，水平方向不变且底部仍有留白；24 项字幕文档及控制器回归、针对性 ESLint 通过。忽略目录 `output/ai-subtitle-position-check/` 保留前后画面与像素边界报告。此项没有运行模型推理，也不代替各平台原生窗口／全屏控制栏交互验收。

## Windows 字幕显示更新竞争修复（2026-10-16）

缓存连续回填时，原流程在发送 `sub-add`／`sub-reload` 后立即写下一份 ASS；Windows 下 mpv 读取文件时可能暂时不允许替换，导致 `EPERM`。只重试文件写入仍会让异步轨道更新重叠，实测出现重复轨道及字幕命令失败。现在主进程等待原生字幕命令完成回执，再写下一份文档；等待期间的新字幕和显示设置合并为最新请求，停止时等待在途更新后移除轨道。原生状态增加未完成数和回执序号，Linux 管道不能用旧快照中的零未完成数提前确认。该查询不消耗播放输入事件，原生调用继续异步执行，避免阻塞渲染线程。[mpv 异步语义](https://mpv.io/manual/master/#synchronous-vs-asynchronous)。

ASS 文件替换仅对 Windows `EPERM`／`EACCES`／`EBUSY` 最多重试五次（总等待 775 ms），保留原完整文件，支持停止取消；磁盘已满等其他错误不重试。持续失败仍保留手动重试入口，日志区分文件写入与播放器命令阶段并记录文件系统错误码，不改变识别与翻译缓存。

本机 Windows x64 的合成视频及真实 libmpv 验证：旧流程第二次替换触发 `EPERM`；仅加文件重试时 150 次更新产生 23 次命令错误、两个字幕轨道；加入完成确认后 150 次更新全部成功，命令错误为零、字幕轨道仅一条、影片只加载一次。证据位于忽略目录 `out/subtitle-display-debug/{before,after,fixed}.json`。此项不代替 macOS／Linux 原生播放验收。修改含原生 addon，需重新构建播放运行库和桌面主进程，并完整重启应用。

## 生成与显示流程并发复查（2026-10-16）

复查范围包含分块调度、缓存复用、准备与模型租约、换片／换音轨、停止／退出、ASS 更新、轨道选择和设置页迟到事件。已复现并修复：

- 音轨准备阶段原来跳过自动重启，旧探测可能长时间占用任务；现在切换音轨立即取消旧准备，且取得模型租约后重新核对播放会话与当前音轨。旧会话不能在换片后重新启用。
- 停止原来等待翻译进程和显示收尾后才取消分块识别；现在先取消识别，再并行收尾。单项清理失败仍继续移除轨道及释放租约。移除原生轨道的完成回执先于 ASS 文件删除。
- 显式显示重试原来可被在途更新写回的旧完成状态覆盖；现在用重试修订区分旧完成与新请求。
- 原全局字幕错误计数会把手动字幕操作失败算到 AI 字幕；现在原生命令带 AI 归属，AI 单独确认自己的未完成数、回执序号与错误。手动字幕失败或慢加载不会暂停 AI 更新，Linux 管道也使用同一归属。
- 初次添加 AI 轨道先保持未选择，加载完成后仅在没有较新手动操作时选中；停止恢复原轨道同样服从较新的用户选择。
- Windows 真实 libmpv 出现 `sid=no`，但缓存的 `track-list.selected` 仍为 `true`。现在独立观察 `sid`／`aid`，并在原生包装层统一修正轨道的选择状态；命令完成与轨道属性观察分别等待。
- 清缓存期间重新开启必须等待删除完成，准备阶段不提供尚未确定缓存身份的清除操作。字幕设置拒绝其他播放会话的迟到事件，并隐藏前一会话的进度和错误。

定向回归覆盖可控延迟的准备、模型获取、识别取消、显示重试、轨道移除、清理异常与缓存删除，以及 Renderer 和 Linux 消息合同。真实 Windows libmpv 使用合成视频与确定性的模型结果替身验证 150 个分块：首次生成合并为 3 次显示更新，缓存重开合并为 2 次且未再次识别／翻译；并发显示更新峰值为 1、轨道为 1、影片只加载一次。两轮手动选轨、刻意制造的手动字幕加载失败、停止后轨道与文件清理均通过；AI 命令错误为 0，两个手动失败分别记账。原生报告位于忽略目录 `out/subtitle-flow-audit/report.json`。此验证没有重跑模型质量／整片性能或 macOS／Linux 原生播放验收。

## 决定

当前持久格式（以已发布 0.8.0 为基线整理）：`local-models.json` 为初版 v1，直接保存三个独立用途、各家族所选精度、目录、下载来源与修订。用途以 `usage` 为唯一事实来源，不再复制旧的共享翻译字段；开发期 v1–v5 的递进兼容已移除。正常读取不改写文件，未知或损坏配置保留原文件并阻止推理；用户显式保存有效用途才恢复。下方日期章节中的 v2/v3/v4 与旧配置兼容属于历史开发证据，不代表当前支持路径。当前规则见 [开发指南](../../DEVELOPMENT.md)。

- 日语识别：当前为 Kotoba-Whisper v2.0 GGML，默认 Q5_0，可显式切换原始 F16；经独立 whisper.cpp 进程运行。
- 中文翻译：新配置的字幕翻译与本地文本翻译默认使用腾讯 HY-MT2 7B Q4_K_M，保留已有用途选择与 Qwen3-1.7B／HY 各档精度；经应用拥有的本机 llama.cpp 服务运行，各模型使用自己的模板和内部参数。绑定回环地址并使用随机凭据，不使用应用在线模型连接。Hy-MT2 实际许可为 Apache-2.0，不沿用旧 Hunyuan-MT 的许可判断。HY 的真实推理尚未验收。
- 从已授权的影片资源按原始时间提取 16 kHz 单声道音频；不录制系统声音，不改变播放音轨/播放速度。
- 以 30 秒为任务区间，提取时包含边界上下文；当前位置优先，预先处理后续区间。定位取消不再相关的任务，保留已完成缓存。
- 缓存按资源物理身份/版本、音轨、识别及翻译模型版本隔离。日语与译文分别保存。共用模型位于独立 `local-ai` 存储（Windows 标准配置使用 `%LOCALAPPDATA%/Javdex/local-ai`），字幕缓存位于 `cache/ai-subtitles`，任务工作文件位于 `cache/local-ai/work/ai-subtitles`，源影片不改写。
- 生成 ASS 时间轴通过共用原生叠加层显示，支持双语/中文/日语；更新不得重开影片或改变视频尺寸。字幕显示失败只影响 AI 字幕，不终止播放。
- 模型与工具固定版本、来源和 SHA-256；权重与下载型运行库按需下载，macOS 识别／音频 CLI 随应用分发。首次下载需联网，安装后识别/翻译完全离线。
- 不保证任意电脑都可实时：生成跟不上时继续播放，展示已识别原文及生成状态，优先补齐当前区间。

## Windows 独显加速与 CPU 回退（2026-10-16 历史）

Windows x64 内置文本翻译／字幕翻译使用固定 llama.cpp b11435 的 CUDA 12.4 或 Vulkan 包，Kotoba 使用固定 whisper b5130 CUDA 12.4 包或同提交源码构建的 Vulkan CLI。模型权重共用，CPU 工具与 GPU 工具独立安装、校验和修复；原有 CPU 目录不改名。Vulkan whisper 随安装包放在 asar 外，普通用户不需要编译器；构建器固定源码与开发材料的 SHA-256，静态编译并附来源／许可。CUDA DLL 的 NVIDIA 许可独立于引擎 MIT。
