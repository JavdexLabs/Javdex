## 可重复检查

`node scripts/performance/continuous-ui.mjs` 使用真实共享 React 组件、Chrome 与合成的 7,500 项数据。在 1440×900、1000×640 下覆盖外层滚动网格、弹窗网格、固定候选行；每类浏览 100 页、切换 20 次筛选，检查三页上限和 DOM 有界。另检查滚回补读、已选 ID、读取失败重试、方向键跨页、改变列数后的条目定位，以及真实目标清单弹窗的长文本布局。

组件交互测试覆盖各接入表面、完整名称确认、合并计划、身份修订、关闭/重开与旧响应隔离、末页删除、筛选重置及详情返回。原有主网格、批量选择、写真及待确认回归继续运行。

以上是合成数据与模拟接口结果，不是实际用户媒体库测量，也不据此推断实际库查询耗时或内存总量。


## 本地结果

- 合成浏览器检查：每个挂载列表最多保留 180 项（60 × 3）；固定行与网格 DOM 随视口有界。40 项和 100 项接口另由共享 hook 回归验证 100 页上限，分别最多 120、300 项。
- 1000×640：外部网格最多 36 个单元、弹窗网格 21 个、固定行 17 个；1440×900：分别 57、36、22 个。包含预渲染和最多一个焦点保留单元。
- 目标页请求刻意延迟时，方向键等待目标返回后聚焦；窗口宽度改变后，首个可见条目保持在同一行范围内。
- 使用真实目标清单弹窗与真实海报组件检查两种尺寸，详情未增加内层滚动；候选选中区保持固定行高。
- 全量测试发现的既有 Windows 差异已在测试层修正：V16 schema 比较只归一化 SQL 换行；扫描审计夹具使用平台绝对路径。业务代码、迁移版本、数据完整性与事务回滚断言均保持原样。
- 全量测试复跑：2,906 项，2,901 通过、5 跳过、0 失败；另有 8 项打包回归通过。此前一轮 Web HTTP 用例遇到 `fetch: bad port`，单独复测 7 项及全量复跑均通过，未修改 Web 代码；临时端口分配仍是该既有测试的偶发风险。
- 类型检查、TypeScript/CSS lint、领域边界、CSS 架构与控件检查均通过。
- 最终稳定焦点 ID 补齐后，浏览器合成检查及 `npm run build` 再次通过；构建包含桌面产物、运行时检查与现有 Web 构建。

## 清单弹窗布局回归修正

真实批量加入清单行包含 68px 封面、上下各 8px 内边距及边框，实际需要 86px；初次接入却按 68px 虚拟定位，造成重叠。固定高度弹窗又使用默认 360px 列表，造成底部留空。现按 86px 行高、8px 间距定位，并使用 fill 占满剩余空间；窄窗口也保持同行操作，长名称截断。共享虚拟单元约束首个内容的高度，防止内容尺寸与定位尺寸分离。

同时缩减导演、系列、机构卡片的多余元数据预留高度，并约束清单主卡片长名称。浏览器脚本新增真实批量加入弹窗，在两种尺寸下断言实际行高、行间距、底部填充和无横向溢出；相关组件与分类交互回归 48 项通过。
