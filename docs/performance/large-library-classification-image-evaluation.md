# 分类主图候选分页与读取线程评估（BQ / BR）

新增classificationImages.page默认60、最多100，保留完整candidates接口的影片范围、非空封面资格、日期空值次序及ID倒序。组织maker/publisher使用同一videos查询中的OR，双角色关联不重复。count和页读取处于同一事务，不读取文件。实际弹窗只在影片来源且隐私允许时加载，当前候选页独立于待保存ID和原始预览。

## 查询基准

每规模所有影片关联同一机构/导演/系列（机构双角色），日期相同，256字符title及200余字符coverPath。ANALYZE后一次预热、固定顺序3热样本；计时不含断言/JSON，完整oracle保留。不作p95、冷盘、IPC、真实媒体、并发或峰值内存推断。

| 影片量 / 实体 | 旧全量ms / JSON B | 首60项ms / JSON B | 末页ms / JSON B |
|---|---:|---:|---:|
| 10000 / organization | 7.207 / 5,378,895 | 8.058 / 32,328 | 10.061 / 21,481 |
| 10000 / director | 8.617 / 5,378,895 | 8.161 / 32,328 | 10.640 / 21,481 |
| 10000 / series | 6.887 / 5,378,895 | 8.247 / 32,328 | 10.344 / 21,481 |
| 50000 / organization | 62.122 / 26,938,895 | 50.785 / 32,387 | 111.939 / 10,762 |
| 50000 / director | 62.897 / 26,938,895 | 50.397 / 32,387 | 112.123 / 10,762 |
| 50000 / series | 63.463 / 26,938,895 | 50.521 / 32,387 | 111.708 / 10,762 |

**保留风险：** 五万候选的末页约112ms，慢于旧全量约63ms；首60项也约50ms，仍可能阻塞主线程。分页降低了返回/renderer处理和DOM规模，不能称为已解决查询时延。后续优先评估读取worker，再以查询计划/分布证据判断表达式排序索引或keyset；不要将本次小返回体当作O(页大小)的SQL工作量。没有新增持久索引或迁移。

UI浏览器使用真实Modal/ThemeProvider/styles、合成API和本地SVG，两个窗口验证分页/重试/选中原ID保存/隐私请求隔离与控件几何。只证明URL及交互，不证明真实图片协议解码、实际持久化或目标机器性能。原始字段长度与全局在途请求预算仍未封顶。详细证据见[实施记录BQ](large-library-implementation-status.md)。

## BR：实际 IPC 移入共享读取线程

`CLASSIFICATION_IMAGE_PAGE` 直接调用 `catalogReadService.readImageCandidates`，查询工厂使用 worker 的只读连接执行 count/page 事务，没有主线程 SQL 回退。原标签查询与图片查询共享一个 worker、32 个订阅名额、串行执行槽及现有启动/排队/执行期限；合并键包含操作、实体、页参数和数据库 revision。主线程仍读取 revision/PRAGMA，不能称为零数据库调用。

独立探针 `scripts/performance/classification-image-worker-benchmark.ts` 创建五万影片合成库，读取导演末页20项，保持 BQ 的 SQL 不变。一次预热后各3热样本，先同步后 worker；2ms 计时器在读取前启动，读取后留8ms收集间隔。结果为：

| 路径 | 读取耗时 ms | 读取期间计时器回调 | 最大计时器间隔 ms |
|---|---:|---:|---:|
| 同步 writer | 111.007–130.092 | 0 | 111.052–130.161 |
| 共享 worker | 123.851–126.386 | 50–52 | 2.594–2.730 |

启动加首次查询127.288ms；32个同页订阅合并为1次实际发送，返回对象相互独立，页对象10,762字节。计时不含断言/JSON，完整oracle保留；worker耗时包含消息、复制、上下文等开销。这是事件循环响应性证据，不是 SQL 提速、冷启动I/O、p95、真实IPC、峰值内存或 Windows/HDD 保证。

真实只读worker验证三个实体多页结果与同步oracle相等，后续写入可见、结果独立、错误schema拒绝且不修改版本。混合请求测试覆盖共享容量、操作隔离、输入复制、取消后的运行槽保留及换库终止屏障；实际handler测试禁止使用同步查询服务。

深OFFSET/count/sort的计算量仍在，慢图片查询会使标签查询排队。原生SQLite硬中断、字段字节预算、更广入口及平台压力验收仍未解决。BQ交互合同未改变，本批未重复浏览器测试；全量结果及可核验artifact见实施记录BR。

## BS：分页后读取宽字段

保留原资格条件和完整排序，先在 MATERIALIZED CTE 中仅选ID、日期、添加时间及空日期标记并执行 LIMIT/OFFSET，再通过唯一主键读取当前页 code/title/coverPath。外层重复完整排序，避免依赖CTE输出次序。count和回表仍在同一事务，实际IPC继续使用BR只读worker；没有新增索引或schema迁移。

使用同一脚本、同样10k/50k合成数据，在代码修改前后分别执行；各自预热一次、3个热样本，下表为中位数。每次都验证所有返回字段及顺序等于旧完整查询。

| 五万影片实体 | 修改前首60 / 末20 ms | 修改后首60 / 末20 ms |
|---|---:|---:|
| organization | 50.044 / 112.087 | 26.989 / 40.392 |
| director | 50.516 / 111.850 | 27.691 / 40.826 |
| series | 50.854 / 111.293 | 27.407 / 40.500 |

返回字段及字节数不变。宽字段不再跟随候选排序，但资格判定仍读cover_path，count、扫描和深OFFSET仍随数据量增长。先前BQ“末页比旧全量慢”的结论仅适用于当时查询；当前合成夹具末页已低于旧全量约62–67ms。单机热样本不代表p95、冷盘、Windows/HDD或其他数据分布；没有测量本批worker混合负载，不能推断共享排队上限。原175组合、组织去重、WAL快照与真实worker测试共8项通过，静态审查无阻断。
