# 系列与机构列表分页评估（BO）

## 范围与语义

主列表原来通过list返回全部实体。新增page接口默认60、最多100项，保留主名/别名搜索、机构角色、更新/影片数量双向排序、ID稳定次序及原封面选择规则。计数仍包含关联的全部videos，不悄悄改为活动媒体库范围。count与分页位于一个读事务；MATERIALIZED页先选身份和排序字段，再投影该页封面、机构归属等显示字段。旧list合同保持，其他调用者仍需单独审计。

## 合成查询结果

10,000个机构、10,000个系列、100,000部影片，每个实体10部影片；日期全部相同以检验稳定ID次序。ANALYZE后一次预热、固定顺序3次热样本，计时不包含断言或JSON序列化。完整旧结果留作字段等值oracle，不据此评估峰值内存。

| 实体 / 排序 | 旧全列表中位ms / JSON B | 首60项中位ms / JSON B | 末40项中位ms / JSON B |
|---|---:|---:|---:|
| maker / video_count | 30.488 / 1,418,895 | 4.975 / 8,438 | 5.404 / 5,731 |
| maker / updated_at | 30.365 / 1,418,895 | 5.589 / 8,438 | 6.435 / 5,731 |
| series / video_count | 32.249 / 2,007,789 | 3.080 / 11,849 | 3.674 / 8,092 |
| series / updated_at | 32.720 / 2,007,789 | 3.901 / 11,849 | 4.742 / 8,092 |

原查询返回完整数组，新查询返回含items/total/limit/offset的整个页对象；并非同大小结果的纯SQL性能对比。样本显示该夹具中分页减少端到端同步查询工作与返回体积，但3热样本不足以证明p95改善；没有冷盘、Windows/HDD、真实IPC、并发或峰值内存结论。名称和路径仍无单字段字节上限。

## 限制与后续

按影片数排序仍须计算候选实体的关联数量，深offset仍处理前面记录，count/搜索/排序不是O(页大小)。当前查询仍在主线程；是否增加维护统计、索引或转移到读取worker，须结合后续分布/冷盘/并发测试判断。头像队列移除作品数排序的授权不自动扩大到分类主列表。

实际页面分页、URL返回、失败重试、连续100页缓存检查与浏览器证据见[实施记录BO](large-library-implementation-status.md)。完整15/42计划仍进行中。

## BP：导演主列表接入

导演分页复用同一读事务与页内投影，使用directors/director_names/director_id，不添加机构角色过滤或系列owner字段。主页面改用page，保留导演计数、创建/详情导航，卡片改为640缩略图。125实体oracle扩展到导演的四种排序和四种搜索，逐页完整字段与旧list对照。

BP独立夹具同时建立每类10,000实体和100,000部影片，每部关联对应机构、系列和导演，其余采样规则同上。以下为本轮导演结果，不能将BO与BP跨轮差异当作回归判断：

| 排序 | 旧全列表ms / JSON B | 首60项ms / JSON B | 末40项ms / JSON B |
|---|---:|---:|---:|
| video_count | 32.399 / 1,378,895 | 3.163 / 8,198 | 3.986 / 5,571 |
| updated_at | 34.584 / 1,378,895 | 4.318 / 8,198 | 5.204 / 5,571 |

浏览器用真实页面/Shell/QueryClient/styles、合成API和本地SVG替代media协议，导演两种窗口各连续100页后仍为60卡片与1个已完成查询缓存项；URI断言确认导演候选使用size=640。不据此推断真实图片解码/IPC/内存峰值或所有在途请求预算。旧list仍保留，图片选择器与其他完整集合调用不在本批关闭。
