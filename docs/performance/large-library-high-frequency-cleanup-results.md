# 高频目录读取与扫描清理优化（DF）

2026-09-11，按用户新授权实施剩余优先级的第 1、2、3 项。本轮只承接高频重复查询、相应只读 worker 接入和扫描清理分批；DD/DE 的停止决定保留为历史，不再代表本轮状态。代码、专项及全量检查已通过（2850通过、1跳过、0失败）。本轮证据见[DF清单](large-library-results/implementation/batch-df-manifest.json)。

## 实际改动

1. **复用高频查询结果。** 目录 count 与页面分别缓存，换页和排序可复用同筛选的 count；年份、首页与媒体库状态也使用有界缓存。Web 保留原有搜索、可见性及排序规则，分别缓存 count、页面和分类集合。缓存归属于具体连接，提交写入、外部提交或 schema 变化会失效；调用方事务绕过读取和发布缓存，失败结果不发布。count 与页面在同一读快照读取，返回值隔离调用方修改。条数与编码字节预算均有限，超限结果照常完整返回但不入缓存，不声称限制进程 RSS。
2. **接入现有原生只读 worker。** 桌面 `VIDEO_LIST`、`VIDEO_YEARS`、`HOME_LOAD`、`HOME_SEARCH`，以及 Web browse、home、collections 走类型化命令。复用原有串行执行、32 个订阅容量、合并、修订与生命周期机制。Web 在等待后复核会话，断开连接取消订阅，故障明确返回，不回退主线程执行慢 SQL。详情、图片、播放的资源授权继续由原入口执行；没有把全部数据库读取宣称为已隔离。
3. **在提交边界分批清理。** 生产扫描的待确认资源核对、缺失资源清理、延迟目录清理及无资源成员移除在批次之间让出主循环。一般候选页为 128 条，使用单调索引游标，避免每页重扫排序；事务和 SQL 游标不跨等待。业务与审计同批提交后才更新完成计数。延迟目录以同一影片为不可拆分单位，跨多个待移除根目录一起删除并选择主资源；单影片超过页大小时仍保持原子性。任务与根目录只在残余记录检查通过后完成。退出先关闭扫描准入、取消并等待当前任务结束，再关闭数据库。

## 取消、失败和重试

文件扫描失败或取消仍不进入清理。清理开始后取消或失败，已提交批次保留，当前失败批次回滚，后续批次停止；扫描结果和审计记录反映实际提交量。下次扫描核对剩余记录，不重复删除或重放旧审计。旧整体事务路径保留为明确的兼容与对照路径，其测试不代替生产分批路径的故障测试。

这项调整细化 ADR-0014 的取消合同，见 [ADR-0028](../adr/0028-batch-scan-cleanup-at-commit-boundaries.md)。正常失败可发布部分完成的失败审计；异常退出沿用现有启动恢复，将中断运行标记失败并保留条目，不自动将未发布审计解释为完整成功，也不承诺跨重启续跑同一任务。

## 本机测量

全部使用临时合成数据库，无用户数据。macOS/arm64，better-sqlite3 实际 SQLite 3.53.4。以下均为三个本机热样本，不能推出 p95、冷盘、Windows/HDD 或整机最大规模。原始日志与 JSON 在本轮证据清单中列出。

## 仍保留的边界

- 单影片资源集合、单次 SQL/文件系统检查、最终审计发布仍可能耗时；128 是候选页上限，不是硬性的时间或字节上限。
- 当前每页仍会复核相关扫描的全部安全根目录或清理任务；根目录/任务特别多时重复授权成本需要专项优化与测量。
- 无资源成员与无法识别项的新增排除使用当前应用 writer 的 TEMP 状态；不提供多个外部程序同时修改同一库的清理隔离保证。
- 读缓存的失效后计算仍可能昂贵，频繁写入会降低命中率。多库 SQL、深页、全局查询缓存预算、统计维护仍有独立工作；本轮没有新增自动 ANALYZE 或容量 PRAGMA 调整。
- worker 原生同步 SQL 的终止期限、WAL/长期写入竞争、桌面取消贯通、目标平台与长跑验证仍未全部完成。
