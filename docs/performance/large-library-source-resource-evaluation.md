# 扫描清理资源引用分批读取评估（BT）

扫描结束的 `removeMissingAccessibleResources` 原先一次调用 `listSourceManagedVideoResourceRefs` 获取库内全部本地来源资源，再逐项检查、删除和选择主资源。现在默认依赖为 `iterateSourceManagedVideoResourceRefs`，在原清理事务内按资源ID递增、每批256条读取引用，查询完成后才交给删除逻辑。资格仍为local或具有strm_source_path，locator映射和处理顺序不变。

首次枚举读取目标库MAX(id)作为上界；没有事务时拒绝执行，后续页也检查事务仍有效。外部写入受原事务隔离保护；本事务后续新增的更大ID不会无限延长枚举。删除当前行不影响后续主键游标。它不是可跨事务持久化的游标，也不是取消/让出事件循环机制。

## 查询计划的修正

初版只增加ID范围和LIMIT，实际EXPLAIN选择 `idx_video_resources_library_video (library_id=?)` 加 `USE TEMP B-TREE FOR ORDER BY`，可能逐页扫描并排序整个库。最终对该查询指定NOT INDEXED，得到 `INTEGER PRIMARY KEY (rowid>? AND rowid<?)`，从上次ID继续，不重复排序。MAX查询仍可使用现有索引。无需增加持久索引或迁移。

取舍：主键范围包含其他库行，库间ID交错时要过滤其他库数据；256是返回行数上限，不是扫描行数或字节上限。没有测量极端跨库稀疏分布时的吞吐，不宣称所有分布都更快。

脚本 `scripts/performance/source-resource-iteration-benchmark.ts` 创建单库5万/30万local资源，路径超过200字符。ANALYZE后，固定先全量再分批，各预热一次再3热样本；下表为中位数。计时包含枚举和ID校验和循环，不包含断言，不执行文件存在性检查或真实删除。

## 正确性与剩余验收

真实数据库1100混合local/STRM/web资源，含跨库交错，完整字段/次序对照旧list；逐项删除后仍枚举完整集合，事务抛错后数据回滚；事务中新增超上界资源不混入；空库结果为空，无事务拒绝。查询计划测试确认主键区间访问及无临时排序。实际coordinator测试验证先处理再索取下项、unknown路径停止并关闭迭代器；其余离线根/授权/清理回滚/30万级审计序列回归保留。最终27项定向通过。

静态审查未发现生产清理链路阻断。未修改清理的原子性与授权规则，也未提前中断尚未安全枚举的扫描。后续仍需处理审计JSON存取、事务内磁盘检查与其他全量关系读取，进行真实大库/慢盘/并发/长时验收。完整15/42目标尚未完成。

## BU：非主资源删除不读取兄弟列表

进一步检查发现，清理每个缺失资源时，不论是否主资源，都会先调用listResources并复制过滤整个同作品资源数组。非主资源删除后直接continue，这个数组没有消费者。现在仅在删除主资源时加载该列表，保持原读取位置（授权之后、删除之前）及原晋升逻辑。

若同一作品有k条待删非主资源，每次列表长度约r，原路径可能反复传输/过滤约k×r条记录；本次将这些非主资源的兄弟列表查询降为0。不是对整个清理复杂度或所有数据库查询的常数保证：逐资源详情、影片审计和主资源候选查询仍保留。

新增真实coordinator测试提供5000条同作品非主资源，禁止调用兄弟列表查询或晋升，验证5000条全部删除和审计。修改前该测试在首次无用查询处失败；修改后与原主资源晋升/回滚等回归一起通过，共28项定向。该证据验证调用次数及行为，不是耗时或峰值内存测量；不重复运行BT吞吐探针。

## BV：仅来源与扫描页读取完整审计

调用方核查：MediaLibrarySettingsPage始终挂载useMediaLibraryScanController，但scan.latest只供sources页ScanSettingsTab显示扫描历史；general/scraping/display/danger页没有摘要消费者。因此本批不新增摘要接口，直接由实际页面传入loadLatest控制快照查询，默认仍为true以保留其他潜在调用方合同。

隐藏时切到独立inactive查询key并禁用，gcTime=0释放不再被观察的完整快照。显式refreshLatest在隐藏状态只标记原key失效，不主动读取；原扫描事件监听、启动/取消逻辑保持。queryFn消费AbortSignal，离开/换库后逻辑取消，迟到结果不会被当前查询采用；这不物理中止主进程同步SQL或IPC，也不构成全局在途请求上限。

sources页新增加载记录、失败信息及重试，避免将尚未返回或失败展示为“尚无扫描记录”。真实hook+QueryClient测试覆盖隐藏首次/refresh/invalidate零请求、完成数据离开后缓存删除、重新进入新请求、ABA及换库迟到结果、错误重试。真实ScanSettingsTab测试区分加载/失败重试/空记录；与原事件作用域回归共7项定向通过。实际父页面tab条件通过源码检查及全量类型门禁，未新增整页浏览器场景或峰值/耗时测量。

完整快照接口未变：进入sources仍会读取整份audit_json及全部unrecognized；下一步后端分页必须同时处理getLatestLibraryScanSnapshot与审计页面合同，不能只替换SCAN_AUDIT_GET。旧summary还可能携带路径数组，不能仅凭类型名将其称为固定字节摘要。此批减少不必要的触发和缓存驻留，不关闭PERF02/06/08全部风险。
