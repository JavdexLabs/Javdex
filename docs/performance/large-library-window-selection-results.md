# 分页窗口、大选集与剩余浏览入口（DG）

2026-09-11，按用户授权执行剩余优先级第4项。承接 PERF-05/06，当前分支为 `codex/large-library-performance`；工作区保留前序未提交改动。本轮没有迁移业务数据库。

## 实现范围

| 入口 | 现在的读取和保留方式 |
|---|---|
| 媒体库影片 | 每页200条，单个挂载列表至多保留3页；网格使用绝对索引和总数 |
| 全局搜索、首页搜索 | 每页120条，同一窗口机制 |
| 演员主列表 | 每页240条，同一窗口机制；状态汇总与页面读取一致 |
| 导演、系列、机构详情的关联影片 | 单页60条，页码写入 `relatedVideoOffset`，嵌套详情返回保留页码 |
| 清单主列表 | 服务端搜索/分页，单页60条，页码写入 `playlistOffset` |
| 单部/批量加入清单、导入目标 | 按需单页候选；导入仅在追加模式加载目标；完整名称是否已存在由后端查询全库确认 |

窗口淘汰不缩短滚动区域。滚回旧页时重新读取该位置；页读取失败保留总数和已有网格，缺失位置提供重试。筛选切换后的旧响应不能覆盖当前结果。非活动卡片页立即回收，返回时只刷新活动且过期的查询；滚动记忆及读取锚点分别只保留20个轻量条目。这里的3页预算是**每个已挂载列表**的预算，不是整个应用所有对象共享3页；保留的嵌套列表各占自己的窗口。

## 选择与批量操作

选择状态独立保存 ID，淘汰卡片页不会丢失选择。Shift 范围使用绝对索引，按页串行补读，结果只保留 ID；提交选择前核对范围完整性、端点、重复 ID、总数与读取修订。修订来自同一 SQLite 读事务，覆盖连接身份、本连接变更和其他连接提交。范围取消、筛选变更或读失败均不提交半个范围，界面显示忙碌或错误状态。

删除和移出媒体库共用每个页面最多4个在途请求的预览队列。取消后等待已有请求结束，后续任务再开始，避免快速开关弹窗叠加并发。大选集仅保存每项 ID、修订和影响数量；单项确认仍显示详细影响。实际提交保留每项 `expectedRevision` 校验。

大选集 ID 和必要修订仍为 O(选择数量)，不会被误称为固定内存；本轮移除的是对已选完整影片对象、全量影响树和无限并发的依赖。批量写入沿用原串行提交和部分失败提示。

## 卡片与查询边界

影片/演员卡片在进入 renderer 查询缓存前投影为展示字段，去除简介、原始元数据及裁剪等大字段；单页按 JSON UTF-8 编码检查1 MiB准入预算。它约束保留的页面载荷，不是 JS 堆或 RSS 上限。遗留 list/GET 合同继续提供完整对象，不能把这项优化描述为所有 IPC 宽载荷已经消失。

清单独立的窄分页 API 先选本页 ID，再补计数、封面与所属关系；展示名称/描述有长度界限，原始数据和名称判重不依赖截断标签。视频成员隐藏、归档或无资源时仍按原全局清单语义计数。

## 验证

浏览器使用实际 `useWindowedCatalog`、虚拟网格和样式，IPC与图片为临时合成夹具，未访问用户数据。每组连续浏览100页，切换20个筛选；包括绝对索引、旧页淘汰后选择显示、滚回补读、失败时几何保留与重试。

| 浏览器尺寸 | 影片卡片最大保留数 | 演员卡片最大保留数 | 最后可见区域DOM（影片/演员） | 最大页缓存 |
|---|---:|---:|---:|---:|
| 1000×640 | 600 | 720 | 18 / 30 | 3 |
| 1440×900 | 600 | 720 | 36 / 63 | 3 |

四组无横向溢出和页面异常，筛选变化归零。此脚本以手动selected Set验证网格显示合同；实际 `useRangeSelection` 和 LibraryPage 的跨页选择、取消及提交修订由组件交互测试覆盖，不混称为浏览器端到端验证。原始红例在改造前浏览100页保留20,000张影片卡片；窗口单测同时验证回退、卸载后锚点恢复、旧响应隔离及同总数修订变化。

专项测试还覆盖真实SQLite分页/旧接口对照、清单60/60/5及页外同名判断、嵌套详情返回、总量缩小、长字段投影、WAL并发写入及连接重新打开。首次全量仅失败于旧worker测试比较连接专属修订；调整为业务结果精确对照，并另外断言修订跨连接不同、同连接稳定。

最终 `npm test` 退出0：2891项测试，2890通过、1跳过、0失败；包含架构/lint、类型和打包检查。`npm run build` 退出0，主进程、worker、renderer、Web及构建产物检查通过。`git diff --check` 通过；受保护冲突测试相对HEAD仍为+27/-0。

[DG证据清单](large-library-results/implementation/batch-dg-manifest.json)包含原始日志、浏览器JSON、8张截图和选定源码快照/哈希。源码patch是相对HEAD的**选定文件累计差异**，包含此前接受的未提交改动，不是独立DG补丁或完整工作区快照。红例为本轮修改前的实际记录，夹具单独保留，不声称可直接在已修改源码上重现旧行为。

## 保留的后续风险

- 深 OFFSET 的数据库查询时间、频繁写入导致的缓存失效、索引/统计调优不因前端窗口而消失。
- 原生在途 IPC/SQLite 查询不能由浏览器 AbortSignal 立即打断；本轮停止后续请求，并隔离过期结果。
- 旧兼容 API 仍传宽DTO，投影前的IPC传输和瞬时分配尚未消除；超大展示字段会触发页预算错误，不截断业务身份。
- 媒体库配置/导航的 `mediaLibraries.list()` 仍返回全量库配置，单库 roots 仍为完整集合。它们不随影片数量增长，但极多媒体库/根目录需另行分页。
- 显式人脸扫描仍使用完整 manifest 和结果集合；头像有/无筛选在主进程仍物化全量结果后分页，最多8份快照但没有单份字节预算。本轮限制了其renderer展示窗口，没有解决这个后端维护/筛选成本。
- 首页固定12项推荐另有当前种子的会话保留；首页快照已设置不活跃查询立即回收，但不把它算作三页卡片预算的一部分。以上限制意味着 PERF-05/06 的全部长跑/字节边界不能整体关闭。
- 本机合成浏览器测试不能替代 Windows/HDD、冷盘、真实图片解码及长时间运行验证。
