# Linux CPU 帧实验验证记录（2026-10-18）

关联 [issue #124](https://github.com/JavdexLabs/Javdex/issues/124)，方案见 [CPU 帧实验](../LINUX_CPU_FRAME_EXPERIMENT.md)。这是开发测试，不是正式发布验收。最终二进制、媒体、helper/addon 和对应源码均应以交付包中的 SHA-256 与构建记录为准。

## 环境与真实输入

- Linux x86_64，Debian 13；无 `/dev/dri`。
- 实际云桌面 Xfce/X11，Electron 43.8.0，sandbox 与 contextIsolation 保持开启。
- 独立 libmpv 0.41.0，明确 SW render API 和 `hwdec=no`。
- 本地 FFmpeg 7.1.5 生成 60 秒 720p30 H.264/AAC SDR 测试图，带运动、四角颜色标记、嵌入字幕与 440 Hz 音频。
- 样片 SHA-256：`d6728c1360c85b85884cd90d03108ed7cf6c36b03926934235b5bedc1e899a03`。

没有把软件 EGL 能力字符串、模拟帧、memfd 单元测试或窗口启动成功当作实际视频显示证据。native smoke、实际 Canvas/GUI 和音频输出分别记录。

## 已执行的检查

### 原生解码和帧所有权

真实 libmpv 解码、SCM_RIGHTS/memfd 字节传输、RGBA 颜色/方向/alpha、连续运动哈希、嵌入字幕和受控生成字幕的实际像素变化通过。生成字幕关闭后同一暂停视频帧恢复精确基线哈希。

完整 smoke 包括暂停 30 秒（无多余帧且时间位置稳定）、持有三个槽位隐藏 10 秒后恢复、seek 到 15/3/25 秒、缩小画布及 1080p 播放区域限制至 720p、停止重开、FD 基线 19→19。另有 84 次快速暂停 seek、30 次连续 load 替换、117 个 generation 的真实媒体压力测试；最终 generation 的像素哈希与单独建立的目标帧一致，而非仅检查元数据。

真实 AAC 经 mpv PCM AO 写出 WAV，检查到非静音浮点样本。该结果不证明扬声器可听或主观音画同步。

最终随包 helper 在没有并行构建/测试负载时预热后采样 15.001 秒，接收并复制 437 帧，约 29.13 fps、107.4 MB/s；helper CPU 时间占单核约 11.1%。该消费端包含像素哈希与测量开销，不包括 Electron IPC、Canvas 和物理显示，不能作为整个应用 CPU 或屏幕刷新率。完整原生检查过程 helper RSS 高水位为 102,932,480 字节，固定像素池为 11,059,200 字节；消费者 FD 基线 19→19。实际 PCM 检查获得 65,536 个单声道浮点样本，RMS 约 0.0110，证明非静音解码数据，未作声音可听声明。


### 自动化、构建和兼容性

新增主进程/preload/控制与界面测试覆盖元数据整数/长度、三帧背压、ACK 归属、旧 generation/旧绑定、隐藏后释放期限、暂停保帧、Canvas ImageData 复用、失败诊断脱敏。现有 DMA-BUF/X11 相关测试继续通过。default CMake 构建仍不启用 CPU/DMA-BUF；CPU-only 原生目标可以单独构建。

最终全量 TypeScript/CSS lint 使用 `NODE_OPTIONS=--max-old-space-size=6144 npm run lint` 通过。默认约 2 GiB V8 堆的首轮 lint 因 heap out-of-memory 退出 134，未把它计为成功或代码诊断；增大仅本次工具进程的堆后独立重跑成功。实验打包清单测试 7/7 通过。 最终 `npm run typecheck` 通过。完整 Electron 测试套件另行重跑，具体通过/失败/取消数量、环境性失败与原始基线复现记录写入交付验证材料；不能把这里的定向通过视作全量通过。

最终 helper 直接 ELF 依赖只有 libmpv、libstdc++、libgcc_s、libc，不直接链接 GL/EGL/GBM/DRM；复用的已审计 libmpv 仍保留其原有运行库依赖。CPU helper 需要 GLIBC 2.34 / GLIBCXX 3.4.21，FD addon 需要 GLIBC 2.33 / GLIBCXX 3.4.21。整个 AppImage 的最低 ABI 还须取所有捆绑 ELF 的最大值，不能只看新 helper。

## 实际 GUI 首轮发现与复测要求

初始开发构建通过正常 UI 把合成目录添加到隔离资料库，扫描后开始播放，可见运动，Canvas 提交计数增加。约 30 秒后出现失败，最后记录约 571 个生产帧、570 个提交帧、三个 outstanding；旧日志只留下通用失败码，不能据此认定具体原因。

初始构建早于已评审的隐藏释放期限修正、ImageData 复用和完整 CPU 诊断映射。并行全量测试/lint 当时正在运行，lint 被终止（exit 137），但没有足够证据把 GUI 失败归因于资源压力。原生审计排除了无条件 30 秒播放计时器和正常 EOF 错误；原始失败日志保留。

复测必须使用独立、不可变的完整 unpacked 包，记录启动前后哈希，停止并行重负载，至少连续播放完整 60 秒样片，并测试暂停、seek、最小化、重开与 HTML 控件。最新固定错误码与固定 origin 不记录原始错误字符串、媒体路径或凭据。最终复测结果随交付证据记录，不能用首轮短时出图宣称稳定播放。

### 固定候选的播放和字幕发现

第二次完整 unpacked 候选正常播完 60 秒样片：生产/传输/复制/Canvas 提交均为 1,717，传输丢帧为 0，mpv 原生丢帧计数为 20。暂停前后相隔 24 秒的截图视频区域像素一致；继续、前后 seek、窗口最大化/恢复、关闭播放器后重开出图通过。正常退出状态为 0，188 个包内文件的运行前后 SHA-256 全部一致。结束时 `RENDERER_REPLACED` 日志对应主动关闭应用，不发生于连续播放中。工具观察与截图保存有额外延迟，不能把样片时长直接用作精确 GUI FPS 的测量分母。

该候选也暴露了真实字幕缺陷：选中的 MOV_TEXT 和外部 SRT 均不可见。相同包内 helper 的桌面原生像素诊断复现缺陷，排除 Canvas 裁剪；四种初始尺寸/resize 情况结果一致。桌面 libass 选择 `OpenAISans-Regular.woff2` 后报告打开字体失败；另一个执行环境选择 Noto Sans TTF 时同样的字幕可见。显式选择 Noto Sans 后，嵌入、外部英文及中文/日文均在桌面原生 PNG 中正常显示，关闭字幕恢复精确基线像素。中日韩文字实际回退至宿主 Noto Sans CJK。

由此增加 CPU-only 的随包 Noto Sans TTF 与 OFL/来源锁，不更改全局字体设置。上述第二候选不能充当字体修正后的最终 GUI 验收；修正后的新固定包须再验证可见字幕、完整播放和控制。

### 字体修正后的固定候选

最终字体候选使用同一 Electron 43.8.0，实际 X11 桌面、`--javdex-cpu-frame --javdex-x11 --disable-gpu` 和独立测试资料目录。完整 60 秒样片正常到达 EOF，嵌入英文字幕在 21 秒和 50 秒的真实桌面截图中清晰可见。EOF 时生产/导出/复制/Canvas 提交均为 1,703，传输丢帧为 0，in-flight 为 0，mpv 原生丢帧计数为 35。外部英文 SRT、中文/日文 SRT 经正常文件选择流程加载后也在 GUI 中可读；暂停与跳转 30 秒通过。这个计数记录不等于测得 30 fps 的物理显示吞吐。 最小化超过 80 秒后正常恢复，应用当时处于暂停状态，继续后时间位置推进且 CJK 字幕保持可见；最大化、前后 seek、关闭播放器后重新播放也通过。最终正常退出状态为 0；仅主动关闭时记录 `RENDERER_REPLACED`，连续播放期间没有失败诊断。 包内 191 个文件运行前后的 SHA-256 全部一致。621 个每秒资源样本中，主进程 RSS 峰值约 301.5 MiB；第一 helper RSS 为 85.9–120.0 MiB、FD 为 70–71，重开 helper RSS 为 85.4–88.7 MiB、FD 为 70–71。RSS 含共享映射，不能将这些数字直接相加当作总物理内存；这也不是数小时泄漏趋势测试。

同一候选首次启动曾在播放 helper 启动前出现横向花屏。原样正常关闭并重开，同一包、同一资料目录和同一参数恢复了正常 UI；首次启动截图及日志保留。与上一正常候选比较，renderer/preload 的 JS、CSS、HTML 和 JSON 字节一致，主进程的差异是字体错误诊断映射及其构建哈希。尚不能确定这次瞬时启动显示异常的原因，不能归为字幕修复已解决的问题。

随包字体原生桌面探针还验证了两种初始尺寸下的嵌入、外部、CJK 和生成 ASS 字幕；关闭与清除字幕恢复精确视频基线。Noto Sans TTF 来自 Debian 官方 `fonts-noto-core_20201225-2_all.deb`，随包附来源、SHA-256 和 OFL；CJK 成功依赖本机 Noto Sans CJK 回退，基础包不包含 CJK 字形。
