# 三平台自动 CPU 回退审计（2026-10-24）

审计基线为 `7af0c06375a65bad24fb5d8bbf635ede45afaed0` 加本次工作区修改。起因是用户反馈：Deepin 25／Hyper-V 中自动模式无法初始化视频，手动 CPU 可以播放。本记录描述源码检查和本机测试，不代表新安装包、远程 CI 或 Deepin 实机验收；已发布的 `0.9.1-beta.1` 仍包含修复前逻辑。Deepin 20 的旧 glibc 兼容已按用户要求排除，Linux 运行库基线不变。

## 结论与修复

自动回退已经存在，但部分故障没有进入共用恢复边界。确认并修复以下分支；没有改变自动／GPU／CPU 的产品语义，也没有新增设置、迁移、重试循环或旧显示后端。

| 缺口 | 影响与本次处理 |
| --- | --- |
| GPU 创建前检查位于捕获边界外 | Linux DRM 设备、DMA-BUF 导入检查可能直接抛普通异常。将设备检查、桥接构造和创建统一纳入图形初始化边界；窗口存在性与运行库缺失仍独立检查。 |
| 部分初始化没有移交所有权 | 工厂抛错前桥接尚未交给包装器，其子进程／监听器可能无人清理。工厂清理临时桥接，Windows／macOS 桥接允许清理未完成的 native.create；清理失败也不阻止 CPU 创建。 |
| 进程通信故障分类不完整 | Windows／macOS 宿主 ready 前队列溢出、postMessage 同步失败，以及 Linux 已退出／不可写／背压／同步写失败路径，可能只有普通异常。现在保存受控故障；GPU 路径允许自动恢复，CPU 路径保持终止。无效控制参数仍是调用错误。 |
| 异步 IPC 与释放回调不经过引擎捕获 | 绑定、解绑、时钟回复、帧回执或最终释放可能在事件回调里抛错。现在记录故障供引擎读取，并拆除监听器；不会用重复 ACK 或强制回收纹理来换取恢复。 |
| 清理异常掩盖原始故障 | 宿主资源清理异常可能使子进程终止步骤未执行。Windows／macOS 用 finally 保证停止子进程，保留原始故障；帧桥接清理异常不再打断所属宿主的失败通知。 |
| 首帧等待从创建而非显示开始 | Windows／macOS 在很晚才显示窗口时可能立即超时。改为从请求显示开始计算，隐藏重置等待，接收器一直不出现仍受限。 |
| Linux 显式禁用 GPU 仍设置 Vulkan | 尊重 Chromium 的 `--disable-gpu`，不再额外选择 ANGLE Vulkan。它与仅切换视频 CPU 的 `--javdex-cpu` 是两个不同层次。 |

Linux 页面关闭原本通过 `RENDERER_REPLACED` 与图形原因区分，没有复现“关页面触发 CPU”的问题。本次进一步显式标注 page／cpu 领域，避免以后依赖本地化文本做推断。

## 环境覆盖矩阵

“统一规则”指共用引擎与适配器的错误分支可由测试覆盖，不表示每一种驱动已经实测。

| 环境 | GPU 路径与风险入口 | 自动模式的预期 |
| --- | --- | --- |
| Windows，NVIDIA／AMD／Intel 独显或核显 | 隔离宿主中的 OpenGL／D3D11 互操作，主进程句柄导入及 Canvas 消费 | 创建设备、导入、自检、渲染或宿主故障时一次 CPU 恢复；不由 `d3d11va-copy` 名称推断具体显卡。 |
| Windows 混合显卡、多屏、远程桌面 | 生产与消费设备不匹配、设备切换、驱动重置、虚拟显示设备 | 能检测到的导入／自检失败进入同一恢复规则；新设备组合仍需真机验证。 |
| macOS Intel／Apple Silicon | 隔离 CGL／IOSurface 生产与主进程互操作，Chromium 消费 | 初始化、通道、自检和宿主故障进入同一规则；本次只有模拟适配器测试，没有 macOS 真机。 |
| Linux X11／XWayland | 活动 GPU 与 DRM 节点匹配、EGL／ANGLE Vulkan、DMA-BUF 布局与导入 | 缺 render node、权限或导入能力时，在会话创建阶段转 CPU；不猜选另一个 GPU。 |
| Linux 原生 Wayland | 显示后端、DRM／EGL、DMA-BUF 与 compositor 消费 | 使用相同控制器、Canvas 与故障分类；不能用 X11 通过推定 Wayland 已通过。 |
| Linux 虚拟机、无直通 GPU、软件合成 | 可能没有可用 DRM 设备或共享纹理能力 | 若主界面已正常启动，GPU 检查／自检失败应转 CPU；Deepin 25 用户场景仍待使用新构建复测。 |
| 任意平台显式 CPU／禁用应用硬件加速 | 独立软件解码、软件渲染、内存帧 Canvas | CPU 设置直接绕过 GPU；应用报告硬件加速不可用时，自动模式直接选 CPU。 |
| 缺运行库、ABI／系统版本不兼容 | 公共解码库、帧传输库或系统依赖无法加载 | GPU 独有能力缺失且 CPU 库可用时可恢复；GPU／CPU 共用依赖同时损坏不能靠切模式解决。 |

## 场景与失败阶段矩阵

| 场景 | 处理与边界 |
| --- | --- |
| 自动／GPU／CPU 三种模式 | 自动至多回退一次并在后续会话保持 CPU；手动 GPU 失败明确报错，显式再次选 GPU 后可重新探测；CPU 失败不进入循环。 |
| 初始化前、桥接创建中、宿主尚未 ready | 纳入图形初始化／通道失败；清理部分创建的对象；同一来源只加载一次。 |
| GPU 进程退出、播放宿主退出／挂起、管道断开／队列过载 | 图形故障按统一规则恢复；Windows／macOS 心跳阈值 5 秒，Linux helper 为 10 秒，另有有界终止。 |
| 无接收器、导入失败、合成色块自检失败、消费池阻塞 | 有界报错并恢复；显示接收等待 10 秒、自检 8 秒、饱和帧池释放等待 5 秒。正常黑场不作为故障依据。 |
| 隐藏、最小化、重新绑定、缩放／分辨率变化 | 隐藏不消耗显示等待预算；时序失效、旧绑定和迟到释放不允许归还新一代槽位；正常暂停持有一帧不等于消费阻塞。 |
| 恢复期间暂停、拖动、切音轨／字幕、换片或关闭 | 保留新控制意图；恢复同一已授权来源及字幕配置；停止／换片取消旧恢复，旧异步回调不得影响新会话。 |
| 挂载外挂字幕与 AI 时间轴 | 通过共用恢复状态重放；可选字幕失败不摧毁已恢复的视频。 |
| 格式不支持、无可播流、已分类的加载／网络／音频错误 | 保留对应错误，不因这些媒体错误重建 CPU；来源授权与有效性检查仍由原会话负责。 |
| 页面导航、renderer 崩溃／关闭 | 终止会话，不创建一个没有页面可显示的 CPU 会话。 |
| 硬解失败后 libmpv 改用软件解码 | 可以继续走 GPU 显示；仅更新 decoderFallback，不能把“软件解码”当成“CPU 画面回退”。 |
| SDR、HDR、4K／高 DPI | GPU／CPU 共用 SDR 色彩合同和尺寸安全边界；无额外 1080p 限制，CPU 高分辨率帧率由实际设备决定。本次没有重做色彩或性能验收。 |

CPU 缓冲实现仍有合理的平台差异：Windows／macOS 最多两帧复制信用，Linux 为三槽 memfd／ACK 池。已纠正播放合同中将“两帧”泛指三平台的描述，未为统一内部数字而重建 Linux 原生运行库。

## 审计时的边界及后续处理

本记录保留当次播放回退审计的范围。随后用户授权补齐第一项中的可检测图形启动故障；已实施范围与新验证见[启动保护记录](startup-graphics-recovery-2026-10-24.md)。入口代码执行前的主进程崩溃等限制仍成立。

- **应用启动恢复独立于视频恢复。** Electron 在主界面创建前因 ANGLE／Vulkan／驱动失败退出，或者应用主进程本身崩溃时，播放引擎尚不能工作。目前没有承诺整个应用会自动重启成软件模式；本次只补了显式 `--disable-gpu` 被覆盖的问题。若要覆盖这一层，需要独立设计启动保护、一次性重启和故障提示，防止重启循环。
- **CPU 也可能失败。** 公共运行库缺失、内存不足、非法尺寸、音频设备不可用、软件 Canvas 无法创建等，仍需受控终止。操作系统或驱动让整个应用卡死／退出时，不保证进程内恢复。
- **恢复原位要求源可跳转。** 不可 seek 的流无法保证从故障前位置恢复；重新打开同一已授权流不等于获得随机访问能力。
- **挂起恢复与设备热切换需真机。** 休眠／唤醒、RDP 重连、GPU 驱动热更新、多显示器插拔、eGPU 与不同 Wayland compositor 的组合，本次没有实际执行。模拟时钟和故障注入只证明相应状态分支。
- **本次没有新包实机结论。** 没有连接用户的 Hyper-V Deepin 25、没有启动 macOS 设备，也没有声称完成全部显卡／虚拟化产品的枚举验收。
