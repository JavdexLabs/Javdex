核对日期：2026-10-13。目标版本为 `0.9.0-beta.1`，目标标签为 `v0.9.0-beta.1`，GitHub Release 必须标记为 Prerelease。本轮检视完成，交付范围为 `dev` 的源码提交与推送，不创建标签、不触发发布；远程正式版仍为 0.8.0。检视基线为 `3e0b581`，覆盖其后的全部未提交改动与新增文件；发布产物须由最终发布提交重新构建，不能复用本地工作区产物。

### Beta 升级包规则补充

按 2026-10-13 用户追加要求，Beta 不再跳过升级包：发布脚本与容器接收端均接受合法预发布版本，使用 node-semver 比较升级顺序；默认在线检查仍只跟踪正式版。发布签名校验与清单生成通过同一模块接口测试，不访问 Docker 或实际发布凭据。

本轮更新专项 30 项通过、1 项 Linux 文件锁测试跳过、0 失败，覆盖两种架构的合成发行闭包实际打包字节、发布签名到接收端校验、Beta 离线上传与安装、`beta.2 → beta.10 → 正式版`、降级拒绝及发布前签名预检。合成架构包不等于两种架构原生依赖验收；Linux 真正单容器烟测已改为升级到签名 Beta，仍待双架构 CI 实际执行。服务端与桌面类型、改动 lint、workspace／导入边界、桌面与服务端构建通过；工作流验证 Beta 和正式版都在上传镜像前检查签名，并附升级包。

## 发布前剩余门槛

- 另行确认触发预发布的范围；本轮提交与推送不包含发布。在发布提交中将 Changelog 的“发布准备”改为真实发布日期，同步待发布文字。只能为完成的发布提交创建一次新标签。
- Release CI 的 Windows 全量检查必须通过，六个启用目标必须由本次提交生成：Windows x64 EXE／ZIP、macOS x64／arm64 DMG、Linux x64 AppImage／DEB。
- Linux amd64／arm64 分别通过更新专项、真正单容器升级验收和基础容器烟测，成功后才上传并合成版本镜像；不以宿主合成进程结果替代容器验收。
- 核对公开安装包、镜像、Compose／JSON 和 SHA256SUMS 的版本及来源一致，Beta 标记为 Prerelease，正式下载和更新接口不切换到 Beta。
- 本次及后续 Beta 均须生成 amd64／arm64 完整升级包和签名清单，附公钥及校验和。仓库级配置列表未发现 `JAVDEX_SERVER_UPDATE_SIGNING_KEY` / `JAVDEX_SERVER_UPDATE_KEY_ID`；包括可能的组织／环境继承在内的发布签名配置须先由管理员确认，缺少配置会在上传镜像前失败。本轮不生成、上传或打印实际发布私钥，详见 [服务端更新](../SERVER_UPDATE.md)。
- 依赖安全复核：最终锁文件的 `npm audit` 报告 36 项（16 moderate、19 high、1 critical）。所有受影响安装路径的包版本与检视基线相同，没有本轮新增受影响版本；critical 为开发依赖 MCP SDK 经 Express 引入的 `proxy-addr@2.0.7`。本轮未执行会扩大改动范围的 `npm audit fix`；发布前应单独评估适用性并修复依赖安全债务，不能把代码回归通过视为安全审计通过。

## 提交前双轴检视

按 code-review 技能独立检查规范与需求，基线为 `3e0b581`，包含全部 tracked 和 untracked 工作区代码。没有扩大为自动发布、生产密钥配置或真实资料库操作。

### Standards

- 两项明确 UI 规范问题已修复：重试保留旧错误与可访问详情并标注更新中，各按钮仅展示自身动作的 busy；版本与运行环境使用共享 `SettingsValueRow`。
- 判断项已处理：生成/接收端共用发行路径、版本 schema 和必需文件合同；单容器 ADR 顺延为 0031，避免与既有模型 ADR 重号；研究文档移除未冻结旧执行器的失效源码链接。
- 一项非阻塞维护建议保留：部署状态只读探针仍直接了解 library 表与任务状态。当前必须通过选中发行包的隔离进程读取，兼容已发布 0.8.0，不能只把新投影加进当前业务包就替换旧版探针；后续变更这些表或状态时，应同步探针与更新验收。该建议不是既有合同违规，也不增加当前发布门槛。

### Spec

- 四项需求缺陷已修复：归档写入失败不截掉已持久上传；提交阶段以权威日志而非提前改变的内存状态判断；首次断线重连后继续重试直至匹配会话可用；最后一块确认不确定时，重新选择同一离线包会继续校验准备，不需重启。
- 防御性改进：管理器在首次异步调用前锁住控制操作并冻结目标，防止混合任务、重复准备和重复停服；HTTP 原有门禁保留。当前 HTTP 门禁已阻止这些内部竞态通过正常接口触发。

### 额外边界修复

- 快照只排除资料根目录的内核锁，保留子目录和独立图片目录中同名文件；禁止图片根包含资料根，完整校验所有恢复目标与配置后才替换资料，补齐任务目录/快照目录持久化。
- 生成密钥的目录检查使用真实路径与严格父子关系，拒绝 `..keys` 和仓库的外部符号链接别名；不生成实际发布凭据。
- 容器打包器构建为独立 JS bundle，临时闭包测试验证其不依赖源码 TS 或 npm 安装目录；CLI 使用真实路径判断入口，避免路径别名导致静默不执行。
- Release 作业增加 GHCR 的只读授权与登录，能读取刚发布但尚未公开的镜像来打包；普通用户拉取镜像仍要求维护者将 GHCR 包公开。
