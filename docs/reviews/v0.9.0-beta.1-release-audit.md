### 首个定向 run：非 root 探针自匹配

`38439873461` 的两种架构均通过服务端构建、`server:test` 和 `server:updater:test`。容器烟测已通过真实 schema 19 → 20 的升级、worker 故障恢复、验证期强制杀死并重启恢复、清单／资料身份保留、单容器及持久发行选择等前序断言；最后非 root 断言得到 `'1000\n0'` 而非 `'1000'`，基础容器烟测因此未运行。不能把前序通过称为整个 run 通过。

探针原先对 `/proc/<pid>/cmdline` 整体文本做包含匹配。`docker exec node -e <probe>` 的内联源码自身包含 `/program/releases/` 和 `/index.js`，所以预期以 root 运行的诊断进程也被输出。修复只按 NUL 分隔后的实际启动脚本参数（argv[1]）判断，非 root 断言仍严格要求唯一输出 UID 1000，生产监督器及 uid/gid 配置未改。

新增回归从真实烟测源码的 TypeScript AST 提取实际 `node -e` 探针，在 VM 中回放业务与诊断的 `/proc` 记录；修复前稳定复现 1000／0 自匹配，修复后两个回归通过，并明确证明真的 root 业务进程及额外业务进程仍会暴露并使原烟测断言失败。该回放不代替真实 Linux 权限检查。
