## 已复现问题

### 0.8.0 授权秘密格式不匹配

正式 0.8.0 的 `generateSecret()` 使用 32 随机字节的 base64url 表示，长度 43；起始候选的统一连接记录及更新网关仅接受 64 字符十六进制。认证成功后仍无法保存连接，原凭据也无法通过更新入口。原迁移夹具错误使用了新格式秘密。

`secret-contract-red` 在真实连接 schema 上复现 1 失败、1 对照通过。保存 schema 与网关共同支持原 43 字符秘密及新秘密，证书、身份、摘要认证和一次性令牌原校验不变；`secret-contract-green` 四项通过。完整连接迁移夹具改为生产秘密生成器后，Electron 的十项迁移测试通过；该命令名仍为 `legacy-secret-red`，但执行测试前源码已经修复，不能把它当作集成红证据，其工作树也非冻结不变。

真实 Linux 容器烟测现先在已发布 0.8.0 镜像中经旧 `bind`／`writer.claim` API 建立授权并实际请求，再更换托管镜像，使用同一 43 字符秘密查询业务、更新状态及设备列表，要求仍只有一个授权。采用后不再为成功路径生成新 `token`。这一增强尚待本轮 Linux CI 实际执行，不以源码检查冒充容器通过。

增量评审发现旧版烟测使用 Docker 映射后的随机端口作为 Host／Origin，而旧宿主只接受容器内部 `127.0.0.1:8096`。真实 WebServer 与 TCP 端口转发复现握手 403；现仅为隔离烟测使用内部 authority，三次握手／授权／状态请求保留身份与凭据断言，只有状态请求携带 bearer，不放宽生产 Host／Origin 校验，也不改变采用后的 HTTPS 客户端。`legacy-authority-final` 一项真实网络回归通过、无跳过，错误 authority 仍被拒绝；该测试已加入更新测试入口及 Node 类型检查。此处不是公开镜像下载或完整容器采用验收。

### 已保存凭据绕过服务身份绑定

连接与备份在核对 `serverId` 前按 `catalogId` 读取凭据，冒用相同资料库 ID 的另一服务可收到 bearer。`identity-red` 真实 HTTP 往返复现连接及备份 list/upload/download 四项失败，同服务恢复资料库对照通过。共享凭据读取入口增加服务身份和未完成迁移身份核对；`identity-green` 五项通过，0 失败、0 跳过，保留同服务恢复后的设备复用。

### 播放请求跨资料库的迟到回调

原生播放确认等待最近播放或稍后观看读取时，替换资料库可能移除新库同 ID 影片。真实会话与业务帮助函数的回归先复现两项失败及一项正常对照，修复后与会话、稍后观看测试合计 32 项通过。

独立检视又确认外部播放器是另一条入口。`external-owner-red` 的 12 个本机／远程等待窗口中 10 失败、2 对照通过；旧调用在启动、配置或资源读取等待结束后，以替换后的资料库记录最近播放，或在最近播放返回后继续移除新库记录。现从请求开始冻结身份与 generation，读取、签发播放地址、启动和业务回调前后均复核，并传入稍后观看入口。`external-owner-controls` 包含不变、换库及同身份新 generation 三组，共 37 项通过、0 失败、0 跳过；原 PlayerService、原生播放与最近播放另 23 项通过。已启动的系统进程不强制终止，但迟到完成不再写入替换后的资料库。
