## 发布期间的修复

- PR 的依赖安装因 npm 镜像返回 HTTP 500 失败。提交 `a2791e0d` 将锁文件中的 462 个归档地址切换到 npm 官方仓库，版本和完整性摘要保持原值。隔离的干净安装及后续 PR CI 通过。[原失败日志](https://github.com/JavdexLabs/Javdex/actions/runs/42639246350)
- 首个发布候选的 Windows 测试有三项失败，原因是字幕发现夹具使用未经规范化的临时路径。提交 `fc82d07b` 将夹具路径统一为实际路径，与生产播放源解析器一致。修复前在 macOS 复现同样三项失败，修复后 Node 专项 6 项、Electron 专项 20 项和正式 Windows 全套检查通过。原候选的打包及发布作业均跳过。确认当时无公开 Release 或固定镜像后，将尚未发布的标签推进到修复提交。[首个候选的失败作业](https://github.com/JavdexLabs/Javdex/actions/runs/42643333599/job/129249995336)
- 修复后的候选首次打包时，Windows 连接 Lua 固定源码地址超时。同一工作流第二次执行仅重跑 Windows 打包及依赖它的后续作业，复用已通过的测试与其他平台构建。11 个发布作业成功，服务端接续入口按条件跳过。[首次打包失败](https://github.com/JavdexLabs/Javdex/actions/runs/42648518936/job/129286767939) · [Windows 打包重试](https://github.com/JavdexLabs/Javdex/actions/runs/42648518936/job/129558015109)
