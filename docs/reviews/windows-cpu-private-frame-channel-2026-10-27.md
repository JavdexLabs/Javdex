# Windows CPU 私有帧通道

2026-10-27；在 `dev` 的 `b463974a` 加上当时尚未提交的 Windows video 接入工作区上继续实现。本轮只扩展 CPU 像素传输，不修改原生播放库、缩放算法、色彩处理或恢复状态机；验收时没有提交、推送或重打安装包。

## 实现与所有权

Windows CPU 与 Mac 复用既有私有 MessagePort：隔离宿主将像素直接发送给 sandbox preload，主进程仅接收／转发经过校验的帧元数据，保留主 frame 的 surface／binding 认证、独立通道代、调度和信用额度。GPU 共享纹理路径及 Linux 的传输方式不变。

原生软件解码／绘制、64 字节行对齐 scratch 和 `napi_create_buffer_copy` 输出复制保留。preload 按真实 stride 构造不透明 RGBX VideoFrame；私有端口输入沿用 Mac 的复制输入策略，不把原生池或外部输入直接交给 video 持有。优化消除主进程对整帧像素的中转与重复序列化，不宣称 CPU 零拷贝，也没有将 Mac 的性能数字套用到 Windows。

两帧信用额度、像素／元数据两路有界配对、未来时间线保留、解绑／换代清理和“同一像素端口先通知退休，再回收生产额度”均继续使用同一实现。正常解绑不报故障；活动端口意外关闭仍有五秒故障预算，CPU 故障保持受控错误，不反复重建或改回 GPU。

手动 CPU、软件界面启动和 GPU 故障后的自动 CPU 接管均使用新通道，无实验开关。GPU 默认缩放、CPU 既有缩放、物理视口尺寸、8192 单边／256MiB 单帧安全边界及最多一次自动回退均未改动。

## 验证

Windows x64，Electron 44.9.3；普通界面使用本机现有 GPU，另独立验证关闭 Chromium 硬件加速的 CPU 播放。原生 addon／libmpv／ANGLE 沿用上一轮 Windows video 验收的同一组二进制，没有重新编译原生依赖。桌面生产构建、Node 类型检查及修改 TypeScript 文件 ESLint 通过。

定向消费者／端口测试 **92 项通过**，宿主／软件桥接测试 **56 项通过**，均零失败、零跳过。原 Mac 私有通道用例扩展为 Windows／Mac 双平台合同，覆盖可信绑定、两帧额度、旧通道回调、元数据不能混入像素、端口关闭、跳转时两路乱序与退休水位。

七组真实 Electron 窗口验收全部通过，均使用隔离资料库和合成媒体，正常退出 `code=0 / forced=false`：

| 检查 | 结果 |
| --- | --- |
| 私有 CPU 通道 | 1080p30／4K24 两份素材播放、暂停定位、画面推进、底栏／展开／全屏、慢消费、停止及重开通过 |
| 像素中转检查 | 私有通道主验收观察到 190 个宿主帧、164 个主进程显示信封；两端像素载荷均为 **0 字节**。软件界面和两类故障接管也分别验证为零 |
| 输出尺寸 | 展开输出为实际物理视口 2394×1247，全屏为 3842×2162（本机窗口／DPI 取整结果），与 native 和 video backing 一致，没有降至 1080p |
| 端口故障 | 从真实 preload 的隔离上下文关闭收到的像素端口；约 **5.34 秒**进入受控 `error`，CPU 宿主退出，未启动 GPU |
| 软件界面 CPU | `--javdex-software` 关闭 Chromium 硬件加速后，真实 video 像素、播放控制、全屏和停止通过 |
| 连续跳转 | CPU 122 次窗口画面采样，零空白；暂停／播放状态下的重复 seek 与恢复通过 |
| SDR／HDR 色彩 | SDR limited/full、HDR10、HLG、缺失 PQ 元数据五类通过；最大 sRGB 参考误差约 1.042 字节值，并检查窗口主色 |
| GPU 故障接管 | 分别主动退出当前隔离 GPU 宿主、终止当前验收应用的 GPU 子进程，均自动恢复 CPU video；进度、音量、静音、倍速及后续控制通过，主进程不接收像素 |
| CPU 字幕 | ASS 和 PGS 两份媒体实际选轨／取消后的差异像素通过，继续检查展示切换、停止和重开 |

实机通道故障首轮脚本误等待不存在的 `phase=failed`，实际应用按合同进入 `phase=error`、停止宿主并正常退出；修正验收断言后重跑通过。首轮报告保留，未改变生产故障逻辑。

## 证据与边界

原始报告在 `out/windows-cpu-private-channel-20261027/final/`，`summary.json` 与 `validation-receipt.json` 记录工作区源码、桌面构建、原生二进制及报告摘要。专用控制台计数和 CDP 端口关闭仅存在于验收脚本，未加入产品入口或公共 Renderer API。

本轮不包含性能配对测量，不能据此承诺固定 CPU 降幅、内存收益或实时 4K60。仍存在原生输出复制、私有 IPC 和 VideoFrame 输入复制。合成截图不证明物理扫描输出、听音质量或任意长时间无泄漏；未重新验收纯核显／AMD／ARM64、Mac/Linux 实机或签名安装包。
