# Windows 互操作模块异步预加载 — 2026-11-07

上轮重启后，主界面就绪后等待 120.1 秒，首次播放同一 NAS 影片仍需 29.69 秒，第二次 1.33 秒。隔离宿主预加载已在点击前约 70 秒完成并被接管，剩余等待中 `playback-interop.node` 的主进程首次加载占 24.07 秒（81%），显卡身份查询约 1.27 秒，图形上下文创建约 0.37 秒。该轮未取得新的 Defender 系统跟踪，因此不将互操作加载耗时直接归因于 Defender。原始证据见 `out/windows-preload-cold-20261107/`。

Windows GPU 预加载现在并行准备两个模块：隔离宿主加载播放运行库，主进程内的 Worker 加载资源互操作模块。Worker 使用 [Node-API 模块的多环境加载支持](https://nodejs.org/api/addons.html#worker-support)，保持 DLL 映射至主线程完成接口绑定，随后退出。互操作 API 的句柄获取／释放仍全部由主线程调用；不在线程间传递原生接口对象或资源所有权。此阶段不创建播放实例、D3D11／ANGLE 上下文或输出纹理，也不访问影片。

首次播放在已有加载尚未完成时接管同一个 Worker；提前于预热触发时也异步加载。等待互操作、宿主模块与显卡选择均就绪后，才按原顺序发送创建及影片命令。维持 60 秒初始化边界、就绪后的 5 秒心跳，以及自动模式下原有的一次 CPU 回退。手动 CPU 不启用 GPU 互操作。窗口关闭和设置变更取消未接管任务，应用退出撤销正在等待的任务；旧结果不能创建已关闭或过期的宿主。不会同时启动第二个互操作 Worker；终止不在主线程同步等待，也不让退出句柄额外保活事件循环。macOS 和 Linux 未新增该预加载入口。

## 验证

真实原生模块原型：Worker 中加载耗时 24.07 秒，期间主线程计时正常；同进程主线程注册耗时 0.83 毫秒，Worker 退出后主线程接口仍能调用。此原型加载同一个实际本地原生库，并不等同于最终包的重启冷态对照。

最终解包应用 `dist/win-unpacked/Javdex.exe` 使用独立资料库及静音合成 H.264，不读取用户影片或截屏，完成 5 个场景：

| 场景 | 结果 |
| --- | --- |
| 等待预加载完成再播放 | 互操作后台加载约 8.08 秒、主线程绑定约 0.32 毫秒，播放模块约 16.75 秒。点击前没有创建播放上下文；复用同一宿主，约 1.15 秒确认 GPU／`d3d11va` 播放，画面自检通过。 |
| 预加载进行中点击播放 | 注入 8.5 秒加载延迟，期间状态查询最长约 19 毫秒；复用同一个 Worker，约 9.53 秒确认 GPU 播放，无提前回退。 |
| 注入互操作加载失败 | 未创建 GPU 上下文，自动切换 CPU，约 2.59 秒确认播放，原因 `GPU_INITIALIZATION_FAILED`。 |
| 手动 CPU | 未启动互操作 Worker，约 0.85 秒确认软件播放。 |
| 模拟加载中退出 | 约 108 毫秒正常退出，无强制结束。 |

另用真实原生注册函数阻塞 5 秒的独立无窗口夹具验证退出，进程在该原生调用返回后以 0 退出（约 5.03 秒）。这区分了可立即取消的异步等待与不可抢占的原生调用；不承诺后者能立即结束进程。最终相关 Electron 回归 222 项通过，主进程类型检查、相关 ESLint、生产构建及包内助手依赖检查通过。
