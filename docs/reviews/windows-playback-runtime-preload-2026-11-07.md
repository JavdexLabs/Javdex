## 范围与行为

## 关闭异常修复与再次打包

用户随后报告关闭时主进程弹出 `TypeError: Object has been destroyed`，调用链为 `detach → stopScheduling → BrowserWindow dispose`。原因是 `closed` 后再次读取原生 `BrowserWindow.webContents` getter；可选链只判断 JavaScript 引用存在，不能保证原生窗口仍可访问。此前测试把该字段建成普通属性，未覆盖原生销毁语义。

现于窗口存活时保存 WebContents 引用，解除监听不再访问已销毁窗口的 getter；调度及迟到读取检查 WebContents 状态，释放操作幂等，并在清理结束时释放未接管的预加载进程。增强测试 fixture 后，原实现可复现用户同类异常；修复后 3 个相关 Electron 测试文件共 43 项通过，主进程类型检查、相关 ESLint 和生产构建通过。

真实 Electron 隐藏窗口的 6 项生命周期检查通过：预加载尚未执行、等待设置读取、模块已就绪、开始播放调度且子进程已被接管、关闭被取消后再接受关闭，以及注册前窗口已销毁。真实验证确认关闭后的窗口 getter 会抛异常，但缓存引用的清理与重复调用安全；关闭被取消不释放预加载，已被接管的子进程不被预加载清理误杀，迟到设置读取不启动新进程。这些检查不显示窗口、不解码用户影片，不等同于可见播放或安装界面验收。

第一次隐藏窗口运行的前 5 项通过，第 6 项因测试假定强制销毁窗口会同步销毁 WebContents 而失败；补充等待真实异步销毁后，完整 6 项通过。原失败和后续完整通过记录均保留，没有把失败结果视为通过。
