# 设置页交互与 UI 检查及优化方案

日期：2026-09-05。对象：当前工作区版本，包含尚未提交的 NFO 与插件卡片改动。

本文件是本次检查的交付报告与实施建议，不是已经落地的功能，也未发布为 GitHub Issue / PRD。

## 1. 结论与检查边界

设置页已经有语义 token、公共按钮、开关、设置卡片、表单和弹窗基础。最需要解决的是：用户无法用一套稳定规则判断“在哪里配置、改动何时保存、影响哪些数据、接下来做什么”。视觉优化应建立在这套规则之上。

推荐保留紧凑的横向分类和桌面工具气质，统一页面标题、设置行、表单操作区和状态表达；常用配置直接可见，关联参数成组编辑，高级功能渐进展开。避免靠更多卡片、更多颜色或更多说明文字表达层级。

检查已覆盖八个一级分类、媒体库五个子页、模型三个子页，以及插件配置、组合插件、供应商、批量任务、扫描审计、NFO 导出等设置页附属交互。核对了入口、状态与事件处理、保存调用、相关 CSS 和公共组件。插件开发助手是独立工作台，本报告覆盖其设置入口和模型依赖，不扩展为助手内部全部工具的评审。

**验证边界：本次是源码与样式静态审查，未完成实际窗口走查。** 自动审批检查拒绝了启动隔离 Electron 实例的命令，仅返回 `blocked by policy`。因此下文将“源码确认”“条件性风险”“设计建议”“待实机验证”分开，不提供虚构截图，不宣称对比度、缩放或实际点击流程已经通过。没有运行批量刮削、文件迁移、加密、导出或删除，也没有修改应用源代码或现有媒体库。

## 3. 已确认的问题与需要验证的风险

优先级：P0 = 首轮解决的操作可靠性问题，并不表示已发生数据损坏；P1 = 本次体验统一主体；P2 = 后续增强。

| 编号 | 级别/证据性质 | 问题与用户影响 | 优化要求 |
|---|---|---|---|
| F01 | P0 源码确认 | 代理页写“地址保存后生效”，但启用开关会把未保存地址一起写入。之后取消地址编辑也无法撤销已经提交的地址 | 地址与启用状态组成一个配置事务；清晰显示未保存；测试、保存不产生隐式互相提交 |
| F02 | P0 源码确认 | 数字步进器 onChange 立即 round/clamp 并调用父级。最短时长又立即发起保存并禁用表单，多位数字的输入过程会被中间值提交打断 | 保留字符串草稿，允许短暂空值；Enter/失焦提交；连续增减在本地完成后合并持久化 |
| F03 | P0 源码确认 | 步进器加减按钮只有 pointer 处理，没有 click/键盘激活逻辑；聚焦按钮按 Enter/Space 不执行增减 | 同一个激活通道覆盖鼠标和键盘，长按另行增强且避免双触发 |
| F04 | P0 源码确认 | 模型子页通过条件渲染切换，编辑草稿存在子组件；切出用途/高级页即卸载，没有未保存保护 | 按配置组保留草稿；离开设置或切换作用域时统一处理未保存改动 |
| F05 | P0 条件性风险 | 模型用途根据 assignment 对象变化重置草稿；媒体库根据 library 更新重置身份和配置草稿。保存别组、重新读取等可能覆盖尚未提交的编辑 | 只同步未编辑字段；dirty 组保留草稿；版本冲突显式展示，不自动抹掉输入 |
| F06 | P0 源码确认 | 主题先更新界面再写设置，写入失败没有回退和本地错误处理 | 失败恢复已保存主题并明确提示；快速切换以后一次选择为准 |
| F07 | P0 源码确认 | 更改图片目录先询问“迁移到新目录”，之后才打开选目录；取消选目录返回原设置，调用方仍提示“目录已更新” | 先选目标，再展示原/目标目录及影响，最后确认；结果区分取消、未改变、成功、失败 |
| F08 | P1 源码确认 | 相同开关视觉有立即保存、需保存、触发全库加解密三种语义 | Switch 专用于即时开关；组内待提交布尔值用 Checkbox；加解密使用明确动作按钮 |
| F09 | P1 源码确认 | 模型 busy 是全局布尔量，一组保存时多张卡都显示“保存中”；代理共用 busy 标记，但另一行仍可能看似可操作、点击后提前返回 | pending 状态绑定具体动作和作用域；只让真实操作显示进度；共享互斥必须明确解释 |
| F10 | P1 源码确认 | 空媒体库设置仅提示从侧栏新建；概览没有可用库时“打开媒体库设置”实际去首页 | 空状态直接提供“新建媒体库”，创建成功后连续进入添加来源与扫描 |
| F11 | P1 设计问题 | 概览同时展示版本、恢复提示、多类状态、两套批量刮削入口和 Agent 工具，首要步骤不突出 | 首次使用只突出当前缺失步骤；已有用户优先异常与运行中任务；每项任务仅保留一处主入口 |
| F12 | P1 源码/设计 | 一级分类大多没有统一页面标题；类别描述未统一呈现；模型子页使用本地 state 与独立样式，媒体库子页使用公共组件和路由 | 统一标题/说明/作用域；统一子导航视觉及 URL 恢复规则 |
| F13 | P1 设计问题 | “默认”同时涉及全局影片、演员和当前库；概览启动影片批量任务使用全局目录，易被理解为当前库任务 | 写清“全局默认”“此库覆盖”；启动区域常驻范围、对象数量、来源与更新模式 |
| F14 | P1 设计问题 | 模型首屏是用途及大量运行参数；无可用模型时 Select 没有主动引导；内置供应商藏在可展开区域 | 未配置时以“添加提供商 → 添加模型 → 设为默认”引导；高级运行参数折叠 |
| F15 | P1 源码确认 | 提供商弹窗允许直接关闭而无 dirty 检查；“查询远程模型/测试”用已保存连接，输入框里可能是尚未保存的新地址或密钥 | 明确测试对象；禁止静默测试旧值；关闭覆盖所有出口；成功保存后清空输入的明文密钥 |
| F16 | P1 设计问题 | 供应商 ID、baseline、Reasoning、Prompt cache 等实现术语直接参与主要阅读路径 | 常用文案中文化；ID 自动生成、详情可改；能力来源及证据放高级详情 |
| F17 | P1 源码确认 | 插件编辑/存储使用 window.confirm，媒体库使用 ConfirmModal，提供商删除使用行内二次确认；插件关闭保护不覆盖父级路由清理 | 使用统一确认组件；保护挂在统一关闭/导航边界；删除影响及依赖在确认前可见 |
| F18 | P1 样式确认 | SettingsCard、模型 assignmentCard、AppFormSection、概览 panel 各自定义标题/内边距；表单和折叠也有多套实现 | 复用少量有明确职责的原语，通过 variants 表达差异，不靠各页复制 CSS |
| F19 | P1 样式确认 | 影片和演员插件各有固定上限的独立滚动区域，外层设置页也滚动；插件多时形成多重滚动 | 插件区随主内容滚动；长字段映射、审计和日志按需要保留受限滚动 |
| F20 | P1 设计问题 | 网络每行显示多个状态标签和重复地址状态；存储目录/加密/覆盖资源多层框与标签并列 | 每组只保留决定下一步所需的主状态，其余用一行辅助文字 |
| F21 | P1 源码确认 | 主题选择仅用 CSS active 表示当前项，缺少选中语义；部分搜索/手动模型输入只有 placeholder | 单选使用 radio/radiogroup 或完整等价语义；输入具有稳定标签；帮助和错误关联到字段 |
| F22 | P1 源码/设计 | AppFormField 用 label 包裹任意 children；URL 字段内又包含多个按钮，不能作为所有复合控件的统一可访问结构 | 拆分 field 容器与 label，提供 htmlFor、hintId、errorId；按钮作为字段旁的独立动作 |
| F23 | P1 源码确认 | 关于页读取版本与部分异步操作没有组件内异常分支；NFO 初始加载失败显示错误但缺少本地重试入口 | Loading/Error/Empty/Ready 成套设计；错误保留在相关区域并提供原地重试 |
| F24 | P1 源码/设计 | NFO 已有正确的预览再执行机制，但设置偏好写入失败时草稿仍留在界面；前台阻塞状态需要跨快捷键、关闭、异常验证 | 区分“本次导出选项”和“偏好已记住”；沿用预览失效规则与前台阻塞合同，不能只为视觉统一改成后台任务 |
| F25 | P1 设计问题 | “迁移来源目录”和“迁移媒体资源”名字相近，前者改变库归属，后者搬动图片文件；防窥与加密也易被混淆 | 名称与说明直接指出对象和结果，危险确认沿用准确的磁盘影响边界 |
| F26 | P1 待实机验证 | 小窗口、系统缩放、长路径、主题对比度、选中与焦点区分、弹窗滚动与遮挡没有实测证据 | 按第 10 节矩阵逐项走查，不能仅以 CSS 存在 focus 或 gutter 判断通过 |

值得保留：媒体库删除已包含范围说明和名称确认；NFO 已有预览失效、文件明细、前台任务保护；防窥已有失败回退；模型提交已有版本检查；设置主滚动区已有 stable gutter；公共 Modal 已有焦点与关闭基础。优化应补齐缺口并复用这些机制。

## 4. 推荐的信息架构

一级分类维持八项，按用户任务调整可见名称；现有路径通过 helper 兼容。

| 推荐名称 | 页面组织 | 常驻首要信息 |
|---|---|---|
| 概览 | 首次设置/异常与任务；紧凑配置摘要 | 下一步、作用范围、需处理事项 |
| 媒体库 | 来源与扫描 / 基本信息 / 刮削 / 显示 / 维护 | 当前库选择器、归档状态、此库生效 |
| 刮削来源 | 影片 / 演员；组合插件与开发入口降为次要动作 | 全局默认来源及是否需要配置 |
| AI 模型 | 用途 / 提供商与模型 / 高级 | 是否可用、实际生效模型；未配置时的配置入口 |
| 外观与隐私 | 界面与影片卡片；详情背景；防窥；智能头像构图 | 显示类即时生效，构图设置与批量处理明确分开 |
| 存储与导出 | 图片资源 / 导出影片资料 | 图片保存位置；导出目标为视频旁 |
| 网络 | 刮削连接 / AI 模型连接 | 直连或代理；配置保存与连接验证状态 |
| 关于 | 版本与更新；项目及许可链接 | 当前版本、检查结果 |

不强制新增第二条纵向导航，避免与应用侧栏竞争。保留一级横向导航，子页采用轻量下划线或弱选中底色；一级与二级不能都像一整排同样的胶囊按钮。

AI 子页纳入 settings route 配置，支持返回原子页与定位。分类、子页和库作用域用 URL 表达；折叠、短期草稿、测试结果放在本地状态。不得把密钥放入 URL、搜索索引或日志。

设置搜索为 P2：入口位于设置标题右侧；结果展示“选项名称 → 所属位置”，点击定位并短暂高亮对应行。支持来源目录/文件夹、代理、防窥/隐私等常用同义词。不索引敏感字段值。无论搜索是否实施，基础导航必须独立可用。

### 新用户的基础路径

1. 尚无库：说明“先添加影片所在的文件夹”，主按钮“新建媒体库”。名称等使用合理默认，颜色和图标可稍后配置。
2. 已建库但无来源：主按钮“添加来源目录”，说明文件仍保存在原位置。
3. 有来源但未扫描：展示当前库、启用目录数和时长过滤规则，主按钮“扫描并导入”。首次扫描前让用户看到会跳过哪些文件。
4. 扫描完成：显示新增、需处理、跳过数量；分别进入媒体库或处理问题。无需把所有日志展开。
5. 资料不完整：引导选择可用刮削来源并补齐资料。代理只在连接需要时配置；AI 模型是相关 AI 功能的可选准备步骤。

引导依据真实状态出现，完成后收成一行，不增加阻塞式多页欢迎向导。不把“尚未配置 AI”渲染成整个应用不可用的警告。

## 5. 统一交互合同

### 5.1 只保留三种提交模型

| 类型 | 适用项 | 统一行为 |
|---|---|---|
| 即时偏好 | 主题、卡片比例、背景、防窥、独立扫描规则、独立排序偏好 | 单次选择立即应用并持久化；局部轻量状态；失败恢复已保存值并给出重试；不要求额外保存 |
| 成组配置 | 提供商地址与凭证、代理地址与启用、插件参数、媒体库身份、头像构图、Agent 运行配置、模型能力覆盖 | 字段直接可编辑；组内“取消更改 / 保存”；完整校验后原子提交该组；保存失败保留草稿；不要每个字段都先点铅笔 |
| 执行任务 | 扫描、批量刮削、重裁头像、加解密、图片目录迁移、NFO 导出、归档与删除 | 描述操作对象与影响；按风险展示预览或确认；执行与结果状态完整；不伪装成普通偏好开关 |

“一致”指相同类型遵循相同规则。无需强行把所有设置改成自动保存，也不增加跨全页的“保存全部”。

具体调整：媒体库默认刮削来源、默认排序/方向、首页发现可以作为各自独立的即时偏好；若排序与方向设计为一组提交，就在整个组内统一采用草稿语义，不再混入即时开关。推荐本轮选择前者。

### 5.2 草稿、导航与并发

- dirty 从“当前草稿与最后保存值”计算；无改动时不显示活跃主按钮，显示淡色“已保存”状态即可。
- 取消只恢复本组；保存只提交本组；其他组的保存、轮询或重新读取不能抹掉本组草稿。
- 在同一页中可保留多组草稿；离开设置、切换媒体库、关闭弹窗、系统返回、快捷导航均经过同一离开检查。
- 提示提供“继续编辑 / 放弃更改 / 保存后离开”；多组改动列出组名。验证失败留在原处并聚焦字段，不执行导航。
- 复杂表单草稿默认仅存内存，不把 API Key 写入 localStorage。普通无密钥草稿是否跨重启恢复作为后续功能，不在本轮默默加入。
- 每个动作有自己的 pendingKey。需要互斥时锁住相关区域并展示原因，不能只在 handler 内忽略点击。
- 同一配置快速变更按序提交或合并为最后值；过期响应不覆盖新操作。模型与媒体库继续保留 revision 检查。
- 服务端版本冲突时保留用户草稿，说明“配置已被其他操作更新”，允许读取新值并检查差异后重试。

### 5.3 文本与数字输入

- 数字编辑过程保留原始字符串；空值是临时输入状态，不能立即等同于 0。
- 即时数字设置用 Enter/失焦提交；重复值不提交；Esc 恢复已保存值。非法范围在字段下提示，不静默把输入改成另一个值。
- 连续步进先更新本地值，松开后合并写入；键盘 Enter/Space 激活加减按钮，数字输入上下键步进。鼠标长按和 click 不重复执行。
- 数字单位紧邻值；用“不限”“使用模型上限”表达业务含义，必要时才展示 0 的存储含义。
- 关联限制在组级校验，例如最小间隔不大于最大间隔；模型/运行上限之间按后端真实约束提示。

### 5.4 保存、测试与反馈

- 组状态统一：未修改 → 未保存 → 保存中 → 已保存 / 保存失败。即时项成功无需每次弹 toast，局部状态短暂出现即可。
- 测试独立于保存，明确说明测试的是“本次输入”或“已保存配置”。测试不顺便保存、不顺便开启代理。
- 若提供商接口只能测试已保存模型，草稿未保存时用可见说明要求先保存，不能在新地址旁悄悄测试旧地址。支持草稿测试需要独立后端接口，列为明确实施依赖。
- 测试结果显示在字段组下：测试对象、结果、时间；失败给出一条下一步，如检查地址、凭证或代理。原始错误折叠且可复制；隐藏凭证。
- 字段变更使旧测试结果失效或标记“配置已更改”；不能继续显示绿色成功造成误解。
- 区分“已配置”“已启用”“测试通过”；配置完整不等于真实连接已验证。
- 业务失败优先落到相关区域；跨页面操作或后台完成才使用全局通知。重试保留用户输入。

### 5.5 任务与危险操作

- 可运行摘要至少包含：对象、作用范围、预计数量或待统计状态、关键策略。
- 加密改为“启用图片加密…”/“关闭图片加密…”，点击后展示影响并确认；处理中区分加密、解密和目录迁移，不能一律标“迁移中”。
- 图片目录迁移顺序固定：选目录 → 校验 → 展示旧/新路径与影响 → 确认 → 进度 → 结果。统计体积、空间检查需要后端能力支持，不能仅在 UI 估算。
- “来源归属迁移”明确磁盘文件不移动；“图片目录迁移”明确会移动资源文件。复用现有安全预览和 revision 校验。
- 统一“暂停/继续”用于可恢复任务；“取消本次扫描/停止导出”保留各任务实际语义；终止不代表回滚已完成内容。
- NFO 保留前台阻塞生命周期；先统一任务视觉和文案。改成后台任务必须另行设计，不纳入本轮样式改造。
- 确认弹窗只对确认按钮使用危险强调；标题点明对象，正文讲真实影响。不可恢复的删除保留输入名称确认，普通偏好不增加确认。

## 6. 各页面的具体优化

### 概览

- 首次使用显示一张紧凑引导区，强调一个下一步；日常使用显示异常和运行中任务，配置摘要使用紧凑键值行或小型状态单元。
- 更新提醒降为一行，并允许忽略；设置恢复失败/损坏恢复优先于普通版本提醒。
- 移除“一键刮削”和下方重复启动按钮的双重入口，保留同一份任务配置与范围摘要。
- 影片批量明确写“所有媒体库的影片资料”；演员默认范围写“未刮削的女优”，高级范围可调整。不能只用“一键”掩盖执行边界。
- Agent 工具变为低强调链接。已有任务仍能查看日志和处理待确认，不为减噪删除能力。

### 媒体库

- 顶部固定当前库选择器与状态，副文案“仅影响此媒体库”；单库也保持稳定位置，避免第二个库创建后布局突变。
- 来源与扫描按“来源 → 扫描动作 → 结果 → 扫描规则”阅读；扫描规则分成常用与高级，运行中保留任务状态。
- 无来源时就地添加；目录行主信息为路径与可用状态，主动作是启停，迁移/移除收进更多菜单，危险操作保留可发现性。
- 最短时长解释从扫描开始前可见；0 显示“不限制”。自动扫描显示间隔、上次完成时间；下一次时间仅在调度器能准确提供时展示。
- 导入 NFO 说明强调首次发现/适用影片的真实条件，不能写成持续双向同步。
- 扫描结果默认给新增、需处理、跳过摘要；详细表格、搜索筛选和日志按需展开。待确认仍回已有收件箱，返回时保留库与审计上下文。
- 未识别文件的“手动导入”和“重命名文件”明确区别，重命名预览显示旧名 → 新名；导入目标沿用明确选择，不自动猜测归属。
- 常规组直接编辑名称、图标、颜色、排序；保存动作就近且统一。显示设置中的 URL 优先级用“列表临时选择优先”解释。
- 归档库显示“已归档，恢复后可修改”，提供恢复入口；删除区独立放底部，不用大面积红底。

### 刮削来源

- 影片/演员使用统一二级导航，减少两套列表及滚动区域竞争；默认来源位于列表顶部并明确全局范围。
- 卡片改为紧凑行：名称、来源/版本、配置状态、简短描述、配置/更多；字段覆盖数量是能力说明，不是质量评分或任务进度条。
- 搜索、排序、清空沿用同一工具栏，空结果提供“清除搜索”；无插件提供导入入口，已有内置但待配置则优先配置。
- 配置操作使用文字“配置”，不让新用户靠铅笔理解入口；导出、删除、AI 调试进入更多。
- MetaTube 配置优先显示服务地址、令牌、测试；访问间隔与支持字段放次级部分。保留现有传输风险确认，改用统一弹窗。
- 组合插件用一句话解释“不同资料字段使用不同来源”，映射表展示不支持/未配置原因。新建组合在高级入口，不与首次连接来源竞争主按钮。

### AI 模型

- 未配置时显示连续路径：选择内置/自定义提供商 → 地址与密钥 → 添加或发现模型 → 测试 → 设为默认。用户可从同一区域完成，避免跳回三个子页寻找下一步。
- 自定义提供商 ID 由名称生成，放高级编辑；地址给出协议对应的格式提示；API Key 支持显示/隐藏、已保存摘要及明确清除动作。
- “可添加提供商”在空状态下默认可见；搜索已配置及可添加结果，不能命中内容仍折叠却显示为空。
- 用途页首屏只保留应用默认、两个用途的跟随/指定、实际模型；思考强度可常显，其余运行参数按组折叠。
- 跟随默认时实际模型为只读摘要；要改成独立模型必须明确选择“独立指定”，不能一改实际模型就悄悄转换继承模式。
- 模型不可用/不支持工具调用时显示当前配置及原因与修复入口，不让下拉框呈现一个与真实配置不同的空白状态。
- 高级页使用“恢复自动识别值”“推理能力”“提示缓存”“长时间缓存”；说明人工覆盖的用途及覆盖优先级。
- 删除提供商/模型前展示用途依赖；已有后端拒绝保护继续保留。删除、关闭、保存采用统一模式。

### 外观与隐私

- 顺序建议：主题 → 影片卡片 → 详情背景 → 防窥 → 智能头像。最常用、影响显示的项优先。
- 主题为四个小型同尺寸预览单选项，显示主题名称与选中标记；支持键盘选择并处理保存失败。
- 影片比例、居中基准复用同一个单选组件；二者各自按即时偏好或组内草稿的合同保存。
- 防窥主开关常显，关闭时仍可查看“已选择的保护范围”摘要并展开配置；不要把子设置完全藏掉。范围为空/再次开启的行为必须可解释，避免无说明地重置全部。
- 明确防窥只影响屏幕显示，图片加密位于存储页；两者可用辅助链接互相解释，但不合成一个模糊的“安全”开关。
- 智能构图保留真实预览，直接编辑草稿并显示取消/保存；构图全部头像是独立任务。保存后不会自动覆盖已有裁切；批量确认继续说明覆盖手工裁切。

### 存储与导出

- 拆成“图片资源”和“导出影片资料”两个子页，避免简单路径设置与复杂导出表单连续堆叠。
- 路径是可选择复制的内容，提供复制/打开目录（如无现成 API，则列为小型接口工作），更改路径使用明确文字按钮。
- 减少重复资源种类标签与多层装饰框；保留一行“用于封面、头像、样张等图片，不是影片来源目录”。
- NFO 保留“选库与目标 → 预览 → 执行 → 结果”；常用内容直显，样张与头像等可选附件保持渐进展开。
- 导出预览摘要突出新增、覆盖、跳过和警告；修改任何影响计划的选项后必须重新预览。兼容限制沿用目标软件的现有说明，不承诺未验证的播放器支持。
- 导出完成分别显示成功/失败/跳过；“完成”关闭报告，不等同于所有文件成功。失败明细可复制，重试基于重新生成的计划，不重复使用失效预览。
- 偏好记忆失败不伪装成导出失败；若本次参数仍可用，分别说明“当前选择可继续使用，但未记住为下次默认”。

### 网络

- 使用可直接编辑的表单，不先显示只读输入再要求铅笔或双击。
- 每种用途一组：使用方式（直连/代理）、代理地址、测试结果、取消/保存。启用与地址同组提交，避免隐式保存。
- 选择直连时保留地址，灰显并说明未使用；选择代理且地址无效时保存被阻止并就地说明。
- 两用途共享组件但保留真实不同请求链路的说明；是否增加“复用刮削代理”属于后续能力，本轮不改变后端代理语义。
- 直连是正常状态，不显示成错误；“未测试”用中性文字，测试失败才使用错误状态。

### 关于

- 应用名与版本为简洁标题；检查更新主动作稳定在右侧；项目、版本页和许可采用紧凑链接行。
- 技术栈等次要内容收起或降低权重；“Release Log”改“更新说明”。
- 获取版本、检查、忽略、打开外部链接失败均有可恢复反馈；下载入口继续明确是在浏览器打开发布页面，不暗示自动安装。

## 7. 视觉系统与组件规范

### 页面骨架

```text
设置                                      [搜索设置…（后续）]
概览  媒体库  刮削来源  AI 模型  外观与隐私  存储与导出  网络  关于

当前页面标题                              [作用域 / 当前媒体库]
一行说明
二级导航（仅有多个子页时出现）

设置分组标题                         [必要的组状态]
  选项名称 + 一行说明                 控件
  选项名称 + 一行说明                 控件
                              [取消更改] [保存]
```

以上是结构示意，不是实机截图或已实现设计。保存区仅出现在成组编辑场景。

| 项目 | 统一要求 |
|---|---|
| 布局 | 沿用现有约 1080px 内容上限；单一主滚动；表单阅读列建议 640–760px，列表可用全宽；不为对称强行双列 |
| 字号 | 沿用设置 token：分组 14px、正文/选项 13px、说明 12px；11px 仅用于非关键信息；页面标题单独建立语义 token |
| 字重 | 标题/标签以 600 为主，必要数字 700；减少到处 700/800 和重复强调 |
| 高度 | 常规控件复用 36px 的 md token；紧凑动作复用 32px 的 sm token；重复图标按钮稳定尺寸 |
| 间距 | 以现有 8/12/16/18px 等语义间距为基础统一映射；卡片采用现有 16px × 18px token；组内用行和细分隔线 |
| 颜色 | 背景用 surface，文字用 text，边框用 border；强调色用于当前选项和主动作，错误/警告仅用于真实异常 |
| 圆角 | 复用现有 radius token，重复单元克制；Modal 沿用项目 12px 规范 |
| 设置行 | 标签与说明在左、控件在右；简单设置单行/双行；复杂字段采用标签在上；窄容器自动上下排列 |
| 按钮 | 每个编辑事务一个主保存按钮；次要动作用 default/ghost；危险确认才突出 danger；保存中不改变按钮宽度 |
| 选项 | 少量互斥项用统一 radio/segmented；较长列表用 SelectControl；草稿多选用 Checkbox；即时启停用 Switch |
| 状态 | 优先短文本，必要才用一个 pill；已配置/已启用/验证通过分别表达；默认不是警告，取消也不一律红色 |
| 焦点 | focus-visible 与 hover、selected 可区分，使用项目 focus token；输入、单选、Tabs、折叠和菜单都必须覆盖 |
| 长文本 | 路径、供应商地址、模型名和错误文本允许换行或截断且能复制完整值；不挤压动作；不将 title 作为唯一解释 |
| 滚动 | 主区域 stable gutter；插件列表随页面；长日志/映射/审计保留局部滚动并限制高度；textarea 预留 gutter |
| 空/错误 | 简短说明 + 当前区域可执行的下一步；滚动卡片用 compact 空状态，固定面板才使用 fill；错误提供重试 |

建议扩展现有原语而非另起一套“新设置 UI”：

- SettingsWorkspaceShell：统一页面标题、说明、作用域、子导航与滚动位置恢复。
- SettingsCard / SettingsSectionBlock：明确 section 与内部分组的层次，减少嵌套边框。
- SettingsRow：描述、控件、pending/error 槽位；SettingsSwitchRow 可作为其便捷组合。
- AppFormField：htmlFor / description / error 的完整关联；复合控件不让多个交互目标嵌在同一 label 中。
- SettingsFormActions：dirty、saving、保存失败与取消；状态驱动按钮，不在各页手写字符串判断。
- SettingsChoiceGroup：主题、封面模式、构图居中等共享单选键盘与视觉行为。
- SettingsDisclosure：统一展开图标、数量/摘要、aria-expanded、aria-controls。
- SettingsConnectionResult：测试对象、结果、时间及失效；网络、插件服务、模型复用。
- ConfirmModal / TaskProgress：复用统一确认及状态视觉，保留任务实际暂停/终止/阻塞差异。

组件样式写同名 CSS Modules，全局只增加必要语义 token；状态用 aria/data 属性。迁移后清理对应 legacy 规则，避免旧全局 class 与新 Module 双重控制同一种视觉。不得单纯复制 ModelUsagePanel 的 field/controlInput 到其他页面。

## 10. 验收要求

### 新用户场景

- 空白数据进入设置，首屏能直接新建媒体库；随后添加来源、扫描、查看结果，流程不依赖 AI 配置。
- 首次扫描前可看见当前库、来源数量和最短时长过滤；能找到短视频被跳过的原因。
- 未配置提供商时能从空状态完成连接、模型选择和默认设置，不面对空白下拉框猜操作顺序。
- 有多个媒体库时，任一修改与任务都能回答“影响哪个库/是否全局”。
- 新用户能区分来源目录、图片资源目录、资料导出位置，以及防窥和图片加密。

### 保存与异常场景

- 代理输入地址后切换启用/取消：未按保存不得提交；测试不提交；测试对象准确显示。
- 数字清空、输入 120、粘贴 600、越界、非法字符、Enter、Esc、失焦、鼠标长按、键盘激活均符合合同；重复值不发请求。
- 模型用途存在草稿时切换子页、保存另一组、刷新数据，草稿不静默消失；库切换、路由返回、弹窗关闭同样覆盖。
- 模拟写入失败、网络超时、凭证无效、版本冲突；输入保留、提示就地、重试可用；主题和即时偏好状态可信。
- 一组保存时只有对应动作显示保存中；其他组能继续编辑或看到真实互斥原因。
- 取消选目录、选原目录、迁移失败和迁移成功分别有正确结果；未选目标前不要求确认迁移。
- 导出预览后更改选项，旧计划不可执行；停止与部分失败有正确报告；运行中关闭、快捷键、返回符合现有阻塞合同。
- 删除/归档/来源移除的影响说明与实际后端行为一致，不把删除记录写成删除视频文件。

### 视觉与键盘矩阵（全部待实际执行）

| 维度 | 覆盖集合 |
|---|---|
| 窗口 | 默认 1380×880；最小 1000×640；宽窗口；以实际 CSS 可用区域复核 |
| 缩放 | 系统 100%、125%、150%；内容缩放另行覆盖到 200% 阅读检查 |
| 主题 | graphite / warm / slate / light 四种，测试文字、输入、选中、错误、焦点 |
| 数据 | 空库；单库/多库/归档库；多目录；长路径和中文长名；大量插件/模型；长错误与日志 |
| 状态 | 首载、空、错误、未配置、未测试、dirty、保存中、成功、失败、冲突、运行中、部分完成 |
| 输入方式 | 鼠标、Tab/Shift+Tab、Enter/Space、方向键、Home/End、Esc；关闭后焦点恢复 |

验收门槛：

- 普通页面和弹窗无被裁掉的关键操作；内容区无无意义横向滚动；展开/错误/滚动条出现时不产生可见宽度跳动。
- 必要按钮和说明不只在 hover 出现；路径和错误可复制；敏感值不泄露到 URL/日志。
- 控件点击区域优先满足项目的至少 24×24 CSS px 要求；正常操作沿用 32/36px 密度。WCAG 对目标尺寸另有间距等例外，本项目无需依赖例外降低常规目标尺寸。[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- 普通文本对比度至少 4.5:1，大文本至少 3:1；禁用态等例外按标准处理。本次未测得实际配色对比度。[W3C 文本对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- Switch 有稳定名称及状态，Space 可操作；帮助文本与控件关联。[W3C Switch 模式](https://www.w3.org/WAI/ARIA/apg/patterns/switch/)
- Tabs 的方向键、Home/End、焦点和面板关联一致；分类导航继续使用链接语义，不把所有导航误改为 tab。[W3C Tabs 模式](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)

实施后的工程检查：运行项目 typecheck、相关组件/状态/路由测试、lint 与 CSS architecture 检查。测试重点是事务、草稿、键盘、路由与错误路径，不为间距和颜色调整编写照抄实现的测试。可视验收必须补实际截图和操作证据，静态检查不能替代。
