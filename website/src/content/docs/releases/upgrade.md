title: "从 0.8.0 升级到 0.9.0-beta.6"
description: "Javdex 0.9.0-beta.6 · 从 0.8.0 升级到 0.9.0-beta.6"
---

1. 确认目标 Release 已提供所需平台安装包；Beta.6 为预发布，须手动选择[对应 Release](https://github.com/JavdexLabs/Javdex/releases/tag/v0.9.0-beta.6)，不通过正式更新提醒获取。使用服务端时，同时核对同版本镜像与对应架构的升级文件。
2. 在旧版中完成或停止任务，可先通过“备份与恢复”创建资料库备份；然后完全退出桌面、正常停止服务，另存完整桌面用户数据目录、自定义图片与模型目录，以及服务端数据、图片和部署配置。应用内备份不含模型配置、Agent 工作记录、最近播放或续播位置，不能代替完整升级备份；原始视频另行保存。
3. 更新桌面；远程部署同步采用 0.9.0-beta.6 服务端。正式 0.8.0 没有托管更新能力，首次须按 [服务端部署与首次采用](/Javdex/server/adoption/) 更换镜像并增加独立的 `/program` 卷，保留原数据卷与媒体挂载。这次基础镜像切换不会自动生成托管升级快照，必须先完成上一步备份；不要执行 `docker compose down -v`。
4. 首次使用新版时，正式数据库 schema 19 在同一事务中升级到 21，模型管理文档 schema 3 直接升级到 4；已有 schema 20 的管理凭据也会保留并迁入多设备授权。已有连接、密钥及用途选择保留。升级后核对媒体库、清单、图片与 AI 配置，再开始新任务；桌面与服务端都使用 0.9.0-beta.6 才能正常管理远程资料。

不要用旧版打开升级后的数据，也不要手动降低 schema。需要回退时，停止新版并恢复升级前完整备份及对应旧版程序。旧开发快照和不完整的开发版数据库不属于正式兼容路径，不能通过改版本号强行升级。
