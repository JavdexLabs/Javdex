---
title: "服务端令牌与客户端更新"
description: "Javdex 0.9.0 · 手动连接、一次性令牌与服务端更新"
---

服务端只提供一个获取一次性令牌的命令：

```bash
docker compose -f docker-compose.example.yml exec javdex node /opt/javdex-manager/index.js token --config /config/server.json
```

命令只输出一条一次性令牌，有效期 10 分钟。桌面与服务端须为相同应用版本。打开“设置 → 存储与导出 → 资料库连接”，选择远程资料库，填写统一 HTTPS 地址，粘贴令牌后点击“完成授权”，保存并重启。测试连接仅核对服务可达及版本，不能代替授权。网页账号密码不能代替令牌。

首次连接自动接受并保存服务器证书，无需确认。合法的公开 HTTPS 证书按系统信任和主机名正常校验，续期或更换无需确认。自签名证书指纹变化时暂停连接，展示新旧指纹，用户确认信任后才继续发送凭据；取消则保留原证书。业务、图片、播放和更新共用该规则。

添加电脑或全部设备遗失时仍使用同一个 `token` 命令。每台电脑领取独立设备凭据，已有电脑继续可用。需要撤销旧电脑时，在已授权桌面的“资料库连接 → 可信设备”操作；不再提供单独的恢复令牌命令。

撤销电脑会停止其管理、授权播放和更新访问，当前电脑须由另一台撤销。维护任务进行中先完成或取消任务；未完成传输可能需要重试。同一资料被其他电脑修改后刷新再编辑，不自动覆盖。

桌面业务、播放、令牌领取与更新共用统一 HTTPS 入口；浏览器还可在同一端口通过 HTTP 只读访问。0.8.0 升级请按[首次采用托管更新](/Javdex/server/adoption/)保留原授权，新电脑才需获取令牌。

可信设备凭据只在桌面主进程的系统安全存储保存。更新协议独立于业务版本，已保存的授权仍可用于同步升级服务端；普通资料管理要求相同版本。

“服务端升级”是服务端版本落后于当前桌面、资料库暂时无法使用时的恢复入口，在版本不匹配页面与连接设置中提供。版本一致或服务端更新时不显示此卡片；服务端更新时应升级桌面。卡片不提供独立的“更新授权”，直接使用资料库连接中保存的设备凭据。

- **在线升级**：由服务端获取与当前客户端**完全相同版本**及服务器架构的官方升级包；例如 0.9.0 客户端只获取 0.9.0 的对应包。获取和校验后点击“确认升级”，核对停服提示，再执行升级。目标 Release 或包不存在时提示失败，不退回其他版本。
- **上传离线包升级**：选择一个与当前客户端版本、服务器架构匹配的官方 `.javdex-update` 文件，例如 `Javdex-server-<version>-linux-amd64.javdex-update` 或对应 arm64 文件。不是 Docker 镜像归档或源码包。版本不一致在上传前拒绝，服务端仍会再次核对签名、目标、版本与迁移路径。
- **备份提示**：如有重要资料，建议升级前使用与当前服务端版本一致的客户端，在“备份与恢复”中手动备份资料库。升级本身不创建、覆盖或轮换备份，现有备份功能保持不变。
- **失败处理**：准备失败时原服务继续运行；安装开始后失败或中断会保持维护状态并要求人工恢复，不自动回退可能已迁移的资料库。
- 续传：重新选择同一升级文件，从持久确认的程序归档偏移继续，不把容器头部和签名 JSON 算入上传偏移。管理进程/容器重启保留偏移；哈希、签名和原生兼容验证通过前不切换程序。
- 完成：自动重新连接资料库，版本一致并恢复访问后隐藏升级卡片。

下载、上传、解压和原生依赖预检期间原业务继续运行。安装须再次人工确认，会中断所有客户端访问与播放。在资料库连接中移除连接授权仅删除本机保存的统一连接与授权；撤销远程设备须使用可信设备列表。已提交的升级由服务端继续执行，撤销发起设备不等于取消升级。

这些入口要求配套的新管理器，不兼容旧管理器。管理器位于基础镜像中，须先更换对应镜像并保留数据与程序卷；仅更新桌面或上传业务包不会更新管理器。更换镜像的操作见[通过镜像升级](/Javdex/server/update/#通过镜像升级)。
