---
title: "停服安装、验证与恢复"
description: "Javdex 0.9.0 · 停服安装、验证与恢复"
---

流程为 `准备 → 停止业务进程组 → 完整快照 → 切换版本 → 迁移并待验证启动 → 持久提交 → 开放业务`。

管理器在数据目录持有内核文件锁，并将锁继承给业务子进程，禁止同一资料库同时运行两个托管写入者。停止会转发信号、等待退出、终止超时进程组并确认退出；`init` 负责孤儿回收。业务意外退出使用有限次数的退避重启，计划更新不触发重启竞争，管理器异常退出由 Docker restart 恢复。业务不得启动脱离监督的后台写入进程。

当前任务的 `current.json` 是上传偏移与提交阶段的唯一权威日志；每个任务目录的 `job.json` 只用于清理归档。归档副本写入失败不丢弃已持久上传的数据；权威日志写入失败会回读记录，提交前恢复，提交结果无法确认时保留现场。快照只排除资料根目录的内核锁文件，子目录和独立图片目录中同名的普通文件仍完整保存；恢复前核对全部快照、配置及目标目录。

安装前检查架构、固定运行环境、签名、期限、升级方向、迁移路径、空间和资料库身份。有扫描、未完成备份或需处理的文件维护时阻止更新，普通待确认资料随快照保留。旧业务完全停止后复制数据库/WAL、独立图片和配置，保留权限/属主并核对快照摘要；不复制原视频。损坏快照不覆盖当前数据。

新版本迁移后先验证真实查询 worker，期间仅开放健康检查，网页、管理与播放返回维护状态。核对应用/schema/资料库身份后持久提交，再开放业务并核对实际握手。不是只检查 PID 或 running 状态，也不是不停机热更新。

提交前失败恢复旧程序和完整数据快照；快照尚未完成、程序尚未切换时，恢复为继续使用未改动的原资料。中断后读取持久记录继续恢复；提交后只继续激活，不自动覆盖可能的新写入。恢复失败或提交后状态不明会显示“需要人工恢复”，保留现场并拒绝下一次更新。

成功后保留当前/上一版发行目录和最近一次完整升级前快照；已结束旧任务按所有权清理，未知、损坏或需恢复的记录/目录不自动删除。清理失败显示警告，新业务继续运行，不因此回滚新数据。
